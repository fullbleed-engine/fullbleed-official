# 2.5.27: document CSS and compositing for inline SVG

Release tag: `v2.5.27`.

Supported SVG paint and font declarations now use the document cascade. Inline
SVG retains HTML selector context, stylesheet source order, print/type/preferred
selection, layers, variables and presentation/inline/important priority. Standalone
SVG assets remain isolated. Paint alpha and inherited fill/stroke opacity are
separate from element/group opacity; isolated native forms composite overlaps
once. Root opacity remains available to explicit child inheritance while the HTML
wrapper owns its compositing. Form reuse records that ownership. Masks retain the
existing binary luminance subset, without continuous soft-mask conformance.

## Verification and publication

1. Build and install the versioned wheel. Regenerate the agent contract, CLI schema
   and `llms.txt` from that installed runtime, then rebuild and install the final
   wheel containing those artifacts. Check release metadata and the bundled Skill.
2. Run the installed-package smoke checks and the full Python suite. Run
   `tools/smoke_svg_styles.py --out target/svg-styles` against the final installed
   wheel and retain all 54 fixtures, 810 checks, PDFs and PNGs. Compare the fixture
   output to the qualified feature build and inspect the final output.
3. Use the clean GitHub release checkout for the worktree gate and complete release
   pipeline, including platform wheels, sdist, native/profile/font/text/layout
   checks and the Linux/Windows SVG output artifacts. Do not publish an unverified
   local wheel or infer registry availability from a tag.
4. Publish the matching Rust crate through its exact-tag workflow. Verify fresh
   public PyPI and crates.io consumers and their retained output after publication.
