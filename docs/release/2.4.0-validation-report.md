# Fullbleed 2.4.0 candidate validation

Date: September 30, 2026. Status: **engineering verification passed locally;
full ISO PDF/VT conformance remains unverified**.

This candidate includes the six-step print roadmap and the 15 earlier
unreleased commits through `0fea628`. Verification used the optimized
Windows `cp310-abi3` wheel in an isolated Python 3.11.8 environment. The
installed native extension, rather than a stale source-tree extension,
supplied runtime behavior.

The expanded veraPDF run found missing CIDSet entries on PDF/A-1 subset font
descriptors. The writer now emits them; both PDF/A-1 specimens passed the final
run. These are exact-specimen results, not a guarantee for arbitrary documents.

Print specimens use a real sRGB ICC as an explicit validation input, not a
runtime dependency. Its SHA-256 and the embedded Inter font's SHA-256 are in
the summary. The required gate checks the documented writer contract through
a separate parser, source-assignment oracles, external PDF/X checks, and
mutation controls. It does not import Fullbleed's native inspector. These
results provide release evidence for the tested features without claiming
exhaustive ISO validation. The optional dedicated-validator path additionally
requires product/version evidence, positive specimens, and negative controls.

## Artifact retention and publication

`target/release-2.4.0/dist/` contains the candidate Windows wheel and sdist.
`target/release-2.4.0/SHA256SUMS` records their hashes. The local evidence archive
and its checksum manifest are stored alongside the distributions. Preserve
these files with CI, release-matrix, and any later dedicated-validator reports.

Both PyPI and crates.io publication workflows depend on the required print
profile gate described in the [runbook](2.4.0-runbook.md). A commercial or
dedicated validator is not required to publish these tested features with
qualified claims. Full PDF/VT-1 conformance must remain unverified in public
claims until additional evidence establishes it.
