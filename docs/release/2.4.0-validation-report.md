# Fullbleed 2.4.0 candidate validation

Date: September 30, 2026. Status: **not released; dedicated PDF/VT gate pending**.

This candidate includes the six-step print roadmap and the 15 earlier
unreleased commits through `0fea628`. Verification used the optimized
Windows `cp310-abi3` wheel in an isolated Python 3.11.8 environment. The
installed native extension, rather than a stale source-tree extension,
supplied runtime behavior.

## Profile specimens

The final harness retained PDFs, manifests, inspection results, raw external
validator reports, input hashes, and replay PDFs in `final-profile-evidence/`.
Its `validation-summary.json` deliberately reports `ok: false` because the
dedicated PDF/VT validator is absent.

| Validation scope | Result |
| --- | --- |
| veraPDF 1.30.2: 11 PDF/A, two PDF/UA, two WTPDF specimens | All 15 passed, zero failed checks |
| pdf_oxide 0.3.78: PDF/X-4 specimen | Passed, no errors or warnings |
| pdf_oxide 0.3.78: basic, multipage, grouped, fixed-binding, and reflow PDF/VT specimens against PDF/X-4 | All five passed, no errors or warnings |
| Internal print identity, hierarchy, DPM, ranges, and replay checks | Passed for the retained specimens |
| Dedicated PDF/VT-1 positive specimens and negative controls | **Not run: no dedicated validator configured** |

The expanded veraPDF run found missing CIDSet entries on PDF/A-1 subset font
descriptors. The writer now emits them; both PDF/A-1 specimens passed the final
run. These are exact-specimen results, not a guarantee for arbitrary documents.

Print specimens use a real sRGB ICC as an explicit validation input, not a
runtime dependency. Its SHA-256 and the embedded Inter font's SHA-256 are in
the summary. The release harness requires the dedicated validator's product
version and selected validation profile, five successful positive specimens,
and rejected negative controls. Internal writer checks and PDF/X-only checks
cannot substitute for that evidence.

## Artifact retention and remaining gate

`target/release-2.4.0/dist/` contains the candidate Windows wheel and sdist.
`target/release-2.4.0/SHA256SUMS` records their hashes. The local evidence archive
and its checksum manifest are stored alongside the distributions. Preserve
these files with any later dedicated-validator reports before publication.

Both PyPI and crates.io publication workflows depend on the dedicated PDF/VT
gate. Configure the runner and validator variables described in the
[runbook](2.4.0-runbook.md), run the exact release source through that gate,
retain its reports, and finish the release matrix before publishing. No
production tag has been created and no registry artifact has been published
for this candidate.
