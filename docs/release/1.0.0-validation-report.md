# Fullbleed 1.0.0 Validation Report

Date: 2026-05-25

This report records the local validation pass used to check that generated
outputs conform to the standards and boundaries asserted for the 1.0.0 release
line. It is evidence for release readiness, not a substitute for the final
clean-commit release run.

## Scope

Validated claims:

- Static HTML/CSS/SVG/image rendering is deterministic within the documented
  static PDF scope.
- Distributed Python wheels are built with `python,svg_raster`, report that
  feature at runtime, and can rasterize SVG fallback-only text.
- PDF profile specimens satisfy internal seed checks, replay determinism, and
  configured external validators.
- CSS coverage claims use the current fixture/report counts, not historical
  or aspirational counts.
- Release-generated artifacts are excluded from the working tree unless they
  are intentional source-controlled fixtures or docs.

Out of scope for this report:

- Browser-equivalent CSS or SVG rendering.
- Dedicated third-party PDF/VT certification. PDF/VT is validated here as
  deterministic PDF/VT-1 seed/DPart support with PDF/X-4 base validation.
- Final publication from a clean release commit.

## Standards Evidence

### PDF Profiles

The profile harness regenerated and replayed 17 profile specimens. The run
validated:

- PDF/A profiles through veraPDF where applicable.
- PDF/UA and WTPDF profiles through veraPDF.
- PDF/X-4 output through `pdf_oxide`.
- PDF/VT-1 seed markers, parsed DPart graph integrity, replay determinism, and
  PDF/X-4 base validation.

Public PDF/VT claim language must remain qualified unless the final release
gate supplies `--pdfvt-cmd` with a dedicated validator.

### SVG

The installed wheel reports:

- `fullbleed.build_features().svg_raster == true`
- `fullbleed capabilities --json` includes `svg.engine_flags.svg_raster_fallback == true`
- The SVG feature matrix separates native vector support, raster fallback
  requirements, and known-loss areas.

The smoke test renders SVG `<text>` through raster fallback and checks for
non-white red pixels in the output PNG.

### CSS And Images

The broad fixture report currently proves `86/86` fixtures, `0` failures, and
`605` assertion/paint checks. The release docs and notes now use those current
numbers.

The launch-specific inline fixture checks that paragraph text, inline-block
content, inline SVG, and inline raster image content stay in one deterministic
inline run. It includes:

- Computed style assertions.
- Layout pixel-run assertions.
- Text trace assertions for visible text.
- Paint assertions for text, inline-block, SVG, and raster image colors.
- Stability-hash verification.

```powershell
python -m maturin build --release --features python,svg_raster
```

The local Windows CPython 3.11 smoke wheel was:

- Path: `target/wheels/fullbleed-1.0.0-cp311-cp311-win_amd64.whl`
- Size: `9497762` bytes
- SHA-256: `0DBAD528E41970EA8D5E2164BF5DE280F172BD150CD08C7D2DD74A2A917A94E2`

Native extension modules and test caches are build/developer outputs. The
checked-in Windows `.pyd` artifact and pytest cache files have been removed
from the release tree, and any locally rebuilt `.pyd` or `.pytest_cache/`
content is ignored/stashed rather than committed as source evidence.

Source-tree Python tests that exercise native APIs require a local
release-feature build first:

```powershell
python -m maturin develop --release --features python,svg_raster
```

Installed-wheel smoke remains the authority for published wheel behavior.

## Final Release Requirements

Before tagging or publishing:

1. Review and commit the intended release source/docs/tests.
2. Confirm `python tools/check_release_worktree.py --json` returns `ok: true`
   with no dirty entries and no tracked artifact violations.
3. Rebuild wheels from the clean commit with `python,svg_raster`.
4. Install each final wheel from outside the checkout and repeat installed-wheel
   smoke.
5. Rerun the PDF profile harness for the exact release commit.
6. Publish only the artifacts built from that exact commit.
