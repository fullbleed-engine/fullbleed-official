# Fullbleed 2.2.3 Release Runbook

Status: final

This patch release publishes the authoritative native-pagination validation fix and the explicit
bank-statement table-fragmentation policy. Release only from the exact annotated `v2.2.3` tag;
registry artifacts are immutable.

## Release Contract

- `Cargo.toml`, `Cargo.lock`, `pyproject.toml`, and CI report `2.2.3`.
- `fullbleed_audit_contract` remains `0.1.3`; the crates workflow reuses the already-published
  audit crate and publishes only a missing main-crate version.
- Wheels retain the `cp310-abi3` tag for CPython 3.10 through 3.14 across all 15 platforms.
- Signed Q32.32 fixed-point layout geometry remains authoritative.
- The Rust engine, 1,642-pass Wheel265 parity evidence, and compiled variable-data performance
  evidence are unchanged from 2.2.2.

## Clean-Checkout Validation

Run from the proposed release commit in a clean worktree:

```powershell
python tools\check_release_metadata.py --expected-version 2.2.3 --json
python tools\check_license_integrity.py --json
cargo fmt --all --check
$env:RUST_MIN_STACK = "4194304"
cargo test --locked
cargo test --locked --features python,svg_raster
cargo check --locked --all-targets --all-features
python build_backend\fullbleed_build_backend.py wheel --out target\validate-wheel-2.2.3
python -m pip install --force-reinstall target\validate-wheel-2.2.3\*.whl
python -m pytest -q
python goldens\run_golden_suite.py --python python verify
python tools\generate_css_parity_status.py --check --json
python tools\check_release_worktree.py --json
```

The component validator must report zero overflow for conservative JIT glyph bounds when the
native pagination trace reports zero actual layout overflow. The bank-statement golden must retain
13 transaction rows on page 1 and five on page 2.

## Packaged Rust and Python Gates

```powershell
rustup run 1.85.0 python tools\smoke_crates_consumer.py --expected-version 2.2.3 --json
cargo publish --locked --dry-run
python build_backend\fullbleed_build_backend.py wheel --out target\release-2.2.3\dist
python build_backend\fullbleed_build_backend.py sdist --out target\release-2.2.3\dist
```

Install and smoke the built wheel, not an editable checkout. Verify the Stable ABI extension,
licenses, specifications, CycloneDX SBOM, wheel tags, and deterministic artifact hashes.

## Publish

1. Commit and push the clean release source.
2. Create and push the annotated tag: `git tag -a v2.2.3 -m "Fullbleed 2.2.3"`.
3. Dispatch `publish-crates.yml` for `v2.2.3` with `publish=true`.
4. Dispatch `release.yml` at `v2.2.3` with `publish_pypi=true`.
5. Create the GitHub release from `ReleaseNotes.MD` and attach all 15 wheels, the source
   distribution, and the SHA-256 manifest produced from the release workflow artifacts.

## Public Verification

```powershell
cargo info fullbleed@2.2.3
python -m pip install --no-cache-dir fullbleed==2.2.3
python -m fullbleed --version
```

Confirm the GitHub release tag resolves to the same commit used by both registry workflows.
