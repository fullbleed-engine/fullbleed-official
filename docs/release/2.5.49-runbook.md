# Stable v2.5.49: generated counter order

## Scope

Generated counter and quote parts are resolved once in authored document order.
Counter identities come from the parent and preceding sibling; their values
come from preceding tree-order content. Layout probes consume the resulting
parts without replaying those logical events. Existing target-text, target-page,
image and leader parts retain their existing resolution paths.

The installed 2.5.48 wheel fails 47 of the initial 59 focused tests; 12 controls
pass. The first functional candidate passes 102 counter, scope and quotation
tests. An additional list-value whitespace control passes on 2.5.48 and fails
on that candidate; the versioned candidate restores the existing trim behavior.
The functional candidate is not a release.

## Boundaries and retained discrepancies

The `contents-before-reset-new-name` witness has a Chromium outer value of 7,
where the current engine scopes it to the contents element. Its initially
handwritten expected value of 0 was wrong as a browser assertion. Preserve the
witness as unresolved; do not count it as a passing parity test.

HTML list start/value/reversed controls preserve existing Fullbleed behavior.
Chromium's explicit `counter(list-item)` values differ in those probes, so they
are compatibility checks. Default markers on `li { display: block }` and general
mutations of default list/footnote numbering are separate remaining work.

This change does not update the 1,662-case external comparison verdicts or
thresholds, and does not claim full CSS conformance, pixel parity, accessibility,
performance improvement or independent adoption. Components remain alpha.
