# Fullbleed 2.2.0 Release Runbook

Status: final

This runbook validates and publishes the compiled variable-data, CSS/layout coverage, and native
vector/raster improvements in `v2.2.0`. Release only from the exact annotated tag; registry
artifacts are immutable.

## Release Contract

- `Cargo.toml`, `Cargo.lock`, `pyproject.toml`, and CI report `2.2.0`.
- `fullbleed_audit_contract` remains `0.1.2`; `subsetter 0.2.6` and its `rustc-hash 2.1.3`
  dependency are disclosed in Cargo metadata, licenses, and the CycloneDX SBOM.
- Python build requirements, runtime requirements, and the `api` compatibility extra remain empty.
- Wheels retain the `cp310-abi3` tag and cover standard CPython 3.10 through 3.14 on all 15
  declared platforms.
- Both shipped Rust crates and the Python distribution remain MIT licensed. Bundled and Cargo
  third-party components retain their recorded licenses.
- The Q32.32 fixed-point geometry contract remains authoritative.
- Performance claims retain the fixed-copy versus distinct fixed-geometry binding boundary in
  `docs/performance-pass-2026-08-04.md`.

## Clean-Checkout Validation

Run from the proposed release commit:

```powershell
python tools\check_release_metadata.py --expected-version 2.2.0 --json
python tools\check_license_integrity.py --json
cargo fmt --all --check
cargo test --locked
cargo test --locked --features python,svg_raster
cargo check --locked --all-targets --all-features
cargo tree -e normal --all-features
cargo tree -e build --all-features
python build_backend\fullbleed_build_backend.py wheel --out target\validate-wheel-2.2.0
python -m pip install --force-reinstall target\validate-wheel-2.2.0\*.whl
python -m pytest -q
python tools\generate_css_parity_status.py --check --json
python tools\check_release_worktree.py --json
```

The expected normal dependency graph is:

```text
fullbleed 2.2.0
|-- fullbleed_audit_contract 0.1.2
`-- subsetter 0.2.6
    `-- rustc-hash 2.1.3
```

The Windows extension must depend on `python3.dll`, never a versioned `python3XY.dll`. Linux and
macOS extensions resolve CPython symbols from the loading interpreter.

## Variable-Data Gate

```powershell
python tools\benchmark_fullbleed_vdp.py --records 100000 --repeats 5 `
  --output target\benchmarks\fullbleed-vdp-100000-final.pdf
```

Require 100,000 distinct verified invoice IDs, one shared static stream, 100,000 unique dynamic
streams, deterministic buffer/file hashes, and at least 100,000 direct-file pages/s. The release
ledger records a five-run median of 337,839 direct-file pages/s on the Windows AMD64 benchmark host.

## Packaged Rust and MSRV Gates

```powershell
rustup toolchain install 1.85.0 --profile minimal
rustup run 1.85.0 python tools\smoke_crates_consumer.py --expected-version 2.2.0 --json
cargo publish --locked --dry-run --manifest-path crates\fullbleed_audit_contract\Cargo.toml
cargo publish --locked --dry-run
```

The already-published audit contract is validated and skipped. The main crate is packaged and
compiled from a fresh consumer lockfile before `fullbleed 2.2.0` is published.

## Python Distribution Gate

```powershell
python build_backend\fullbleed_build_backend.py wheel --out target\release-2.2.0\dist
python build_backend\fullbleed_build_backend.py sdist --out target\release-2.2.0\dist
```

Verify the wheel contains the Stable ABI extension, `fullbleed/_abi.py`, licenses, runtime
specifications, and CycloneDX SBOM. The release workflow builds and installs:

- manylinux2014: x86-64, x86, ARM64, ARMv7, s390x, ppc64le;
- musllinux 1.2: x86-64, x86, ARM64, ARMv7;
- Windows: x86-64, x86, ARM64;
- macOS: Intel and Apple silicon.

The x86-64 manylinux wheel is additionally installed under Python 3.10, 3.11, 3.12, 3.13, and
3.14.

## Tag and Publish

1. Confirm every local gate passes and commit the intended release source.
2. Push the release commit to `origin/master`.
3. Create and push the annotated tag:

   ```powershell
   git tag -a v2.2.0 -m "Fullbleed 2.2.0"
   git push origin v2.2.0
   ```

4. Let the tag-triggered `Release` workflow validate and build the complete distribution set.
5. Publish `fullbleed 2.2.0` to crates.io from the immutable tag; do not republish
   `fullbleed_audit_contract 0.1.2`.
6. Publish the exact validated 15-wheel plus sdist set to PyPI.
7. Create the public GitHub `v2.2.0` release from `ReleaseNotes.MD` and attach those same immutable
   Python distributions plus a SHA-256 manifest.

## Post-Publish Checks

```powershell
cargo info fullbleed@2.2.0
python -m pip install --no-cache-dir fullbleed==2.2.0
fullbleed capabilities --json
fullbleed doctor --strict --json
```

Confirm crates.io reports MIT and not-yanked metadata, PyPI exposes all 16 expected files, the
GitHub release assets match the validated workflow artifacts, and a clean Python environment can
import the compiled binding API and render distinct records. Corrections require a new version.
