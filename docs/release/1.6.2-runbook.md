# Fullbleed 1.6.2 Release Runbook

This runbook validates and releases the `v1.6.2` packaging patch through
`.github/workflows/release.yml` and
`.github/workflows/publish-crates.yml`.

## Patch Scope

The 1.6.1 Rust crate compiled in the repository because `Cargo.lock` retained
the tested Lightning CSS dependency graph. A new library consumer does not use
that lockfile and could resolve `lightningcss 1.0.0-alpha.72`, whose `Rotate`
API is incompatible with the 1.6.1 source.

Version 1.6.2 exact-pins the tested dependency graph:

- `lightningcss = "=1.0.0-alpha.70"`
- `parcel_selectors = "=0.28.2"`
- `time = "=0.3.45"`

The `time` constraint also prevents a fresh consumer from selecting releases
that require Rust 1.88 while Fullbleed declares Rust 1.85.
Six `let` chains that require a newer compiler are expressed as equivalent
nested conditionals so the source itself also compiles on Rust 1.85.

`fullbleed_audit_contract 0.1.1` is unchanged and is already available on
crates.io. The crates workflow skips that existing version before publishing
the patched main crate.

## Supported Python Contract

Fullbleed 1.6.2 supports standard CPython 3.10, 3.11, 3.12, 3.13, and 3.14.
The extension targets `abi3-py310`. The release workflow retains the complete
manylinux, musllinux, Windows, macOS, and source-distribution matrix from
1.6.1.

## Registry Configuration

The existing trusted-publisher records remain:

- Owner: `fullbleed-engine`
- Repository: `fullbleed-official`
- Cargo workflow: `publish-crates.yml`
- Cargo environment: `crates-io`
- PyPI workflow: `release.yml`
- PyPI environment: `pypi`

Both registries use short-lived OpenID Connect credentials. No long-lived
registry token is required.

## Local Release Candidate Checks

Run from a clean checkout:

```powershell
python -m pip install "maturin==1.14.1" "twine==7.0.0" pytest jsonschema
python tools\check_release_metadata.py --expected-version 1.6.2 --json
python tools\check_license_integrity.py --json
cargo fmt --all --check
cargo test --locked
cargo test --locked --features python,svg_raster
python -m pytest -q
rustup toolchain install 1.85.0 --profile minimal
rustup run 1.85.0 python tools\smoke_crates_consumer.py --expected-version 1.6.2 --json
cargo publish --locked --dry-run
python -m maturin build --release --locked
python -m maturin sdist --out dist
python -m twine check target\wheels\* dist\*
```

The lockfile-free consumer smoke is mandatory. It packages the exact main
crate, extracts it outside the repository, creates a new Cargo project with a
fresh lockfile, and compiles the packaged source using Rust 1.85. This gate
must resolve:

- `fullbleed 1.6.2`
- `fullbleed_audit_contract 0.1.1`
- `lightningcss 1.0.0-alpha.70`
- `parcel_selectors 0.28.2`
- `time 0.3.45`

## GitHub Validation

1. Run the `Release` workflow with `publish_pypi=false`.
2. Run `Publish crates.io` with `release_tag=v1.6.2` and `publish=false`.
3. Confirm both workflows pass the packaged-crate consumer smoke.
4. Inspect the complete wheel, sdist, and Cargo package artifacts.

## Tag and Publish

After the release commit is clean, pushed, and validated:

```powershell
git tag -a v1.6.2 -m "Fullbleed 1.6.2"
git push origin v1.6.2
```

Publishing remains explicit:

- Dispatch `Publish crates.io` with `release_tag=v1.6.2` and `publish=true`.
- Dispatch `Release` with `publish_pypi=true` only if the aligned Python
  1.6.2 distribution should also be published.

Published files are immutable. Never attempt to overwrite 1.6.1.

## Post-Publish Verification

Use fresh consumer environments:

```powershell
cargo info fullbleed@1.6.2
cargo add fullbleed@1.6.2
cargo check
python -m pip install --no-cache-dir fullbleed==1.6.2
python -m fullbleed --version
python -m fullbleed doctor --strict --json
python -m fullbleed compliance --strict --json
```

Confirm that both registry packages report MIT and that `fullbleed 1.6.2`
compiles without a consumer-supplied dependency override.
