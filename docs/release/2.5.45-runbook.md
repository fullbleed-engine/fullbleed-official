# Stable v2.5.45: compiled reflow font selection

This patch carries the font-cache correction in PR #147 onto stable 2.5.44.
A changed value must select its fonts correctly, including when switching
between primary and fallback fonts or between CSS character ranges.

## Required evidence

1. Retain the public 2.5.44 negative control: the 20-case independent-reader
   suite has 15 failures and five passing controls on Windows. The original
   Inter/full-CJK-font reproducer also records missing Japanese text and the
   reverse switch to an incorrect font. These are synthetic regression cases.
2. Build and install the final stable wheel, generate agent artifacts from that
   runtime, then build/install the final wheel and sdist. Check contracts,
   synchronized release metadata, installed behavior, package descriptions,
   licensing and the bundled Skill. Retain the full native/Python qualification
   for the unchanged implementation and rerun the focused reader checks with
   one and four workers against the final wheel.
3. Require final-source Windows/Linux CI. Retain the
   `compiled-font-fallback-*` artifacts: saved PDFs, PDFium previews, pypdf
   text/font reports and JUnit results. Check the existing compiled-reflow WASI
   fixture separately; its prior cases cover replay, glyph changes, input
   rejection, cancellation and recovery, not general font parity.
4. Compare all 1,662 unchanged corpus fixtures with stable 2.5.44 using the same
   references and thresholds. Retain failures and disputed references, and
   investigate any changed raster, verdict or PDF bytes.
5. Publish through the existing workflows after source review. Verify public
   distribution hashes and fresh Python/Rust consumers, including the changed
   font-selection behavior, before calling the patch shipped. Retain the
   source, baseline, PDF and reader evidence with the release.

## Scope and limitations

The stable 2.5.44 source corpus has 1,624 PASS, 20 FAIL and 18 disputed
references. Its all-pass gate is not green. Development results use a different
baseline and cannot substitute for this comparison. Dedicated PDF/VT validation
remains unavailable. These checks establish the recorded regression behavior;
they do not establish general CSS parity, conformance, accessibility or throughput.

Fallback fonts must still be registered. The public API is unchanged: this fix
does not add a compiled glyph-report API or expose compiled VDP in Node 0.8.7.
Component authoring remains alpha and independent adoption is unconfirmed.
Evidence is retained under
`target/growth/first-document-feedback-20261029/fallback-fix/`, with final stable
package qualification in its `release-2545/` subdirectory.
