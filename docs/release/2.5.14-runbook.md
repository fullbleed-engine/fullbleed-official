# 2.5.14 Arabic text and styled bidi release

Target release tag: `v2.5.14`.

1. Run the focused bidi and Unicode-map Rust tests, then the full Rust library
   suite. Build and install the final-version wheel before installed checks.
2. Run `tools/smoke_rtl_text.py` against the installed wheel and retain all PDFs,
   both reader outputs, glyph diagnostics and native/PDFium previews. Inspect
   the rendered Arabic, isolated identifiers, nested styles and wrapped lines.
   The pinned font and OFL notice under `tests/fixtures/rtl` are test assets;
   they are not added to the core runtime font bundle.
3. Run focused Python RTL, text-extraction and inline-wrapping tests, the full
   Python suite, and independent font-subset checks. Validate the bundled Skill.
4. Regenerate agent artifacts with `tools/generate_agent_contract.py` from the
   final installed wheel, rebuild the wheel with those generated resources,
   then check generation, license integrity and release metadata. Require full
   PR CI, including Windows/Linux RTL output and the existing 17-profile gate,
   on the exact source commit before tagging.
5. Publish through the trusted PyPI and crates.io workflows. Verify fresh public
   consumers and retain package checksums and workflow evidence before releasing
   the bilingual invoice starter that depends on this fix.

No new standards-conformance claim is made. The existing dedicated PDF/VT
validator limitation remains. Source/tag order and reader-specific visual
reconstruction are distinct; PDFium can rearrange an alphanumeric identifier
in a mixed RTL line even in a browser-generated reference PDF. Check field
geometry and the Unicode text with independent readers rather than equating a
single reader's entire output with the source document.

Node and .NET packages require separate engine upgrades and verification.
