# 2.5.31: rich table content ownership

Release tag: `v2.5.31`.

A paragraph, styled span, list, figure or nested table inside a cell could open
its own marked-content ID inside the cell's ID. The source accessibility check
and a PDF/UA profile boolean did not detect this reliably. Rich TH/TD cells now
form structural groups; their descendants retain the content IDs. Plain cells
keep their original content owner. Native untagged runs inside a rich cell are
assigned a leaf Span without overlapping existing semantics or artifact scopes.

Cell borders and backgrounds precede the cell's content tag, allowing the
writer to classify them as artifacts for tagged profiles. Ordinary PDF output
is unchanged. Header scopes, spans, explicit Headers references, alternative
text, reading order and content ownership remain part of the release gate.
See [issue #97](https://github.com/fullbleed-engine/fullbleed-official/issues/97).

## Candidate evidence

- The public 2.5.30 wheel fails 135 of 180 saved-PDF cases; its 45 plain-text,
  CSS-bold-cell and paragraph controls pass. Keep the failed PDFs and inputs.
- The local development candidate passes all 180 cases and repeated-render
  determinism checks: three profiles, twelve document families and five output
  modes, including tables split between rows. Text, paint programs, table
  relationships and figure alternatives match the baseline. All 15 independent
  PDFium preview pages retain their pixels.
- All 60 untagged PDFs retain the public release's bytes. The six original
  component-export HTML/CSS examples retain text and pixels and pass veraPDF
  1.30.3's PDF/UA-1 profile with clean stderr.
- Native validation passes 1,389 tests and 11 doctests. The installed debug
  wheel passes 80 focused Python tests. Require the final optimized wheel and
  full Python suite below before publication.
- The first development attempt failed two existing reading-preview tests.
  The next attempt exposed a checker error for painted list labels and added
  unnecessary artifact markers to untagged output. Retain those rejected
  attempts and their logs; neither is a release candidate.

## Known independent limitation

Eleven unchanged table fixtures already fail PDF/UA-2 caption containment rules
in veraPDF 1.30.3. Captions can be emitted outside their logical table, with a
nested Caption element. This remains tracked in
[issue #98](https://github.com/fullbleed-engine/fullbleed-official/issues/98).
Keep those fixtures and compare the external rule failures without suppressing
them. A clean nested-MCID check does not establish general PDF/UA conformance.
The experimental component alpha needs its own qualified native update.

A separate stress probe with a single oversized rich cell failed to finish
within the observed time limit on both the public release and the development
candidate. The reduced twelve-paragraph case emitted no PDF before both runs
were stopped after about 117 seconds. This is tracked in
[issue #99](https://github.com/fullbleed-engine/fullbleed-official/issues/99).
The passing row-pagination cases do not verify that input. Retain its source
and timeout observations, and resolve it separately from this tagging change.

## Publication gates

1. Build and install the final optimized 2.5.31 wheel. Regenerate the agent
   artifacts from that installed runtime, rebuild, and install the final wheel.
   Run focused and full Python tests, installed-package and metadata checks,
   the bundled Skill validator and unchanged golden-document checks.
2. Retain all 180 saved PDFs and their structure, text, font and pixel evidence.
   Require zero nested/repeated content IDs, unique structure/parent-tree
   ownership, preserved table relationships and repeated-render determinism.
   Compare all 60 untagged PDFs with the public 2.5.30 baseline.
3. Run independent PDF/UA-1 and PDF/UA-2 validation on the saved direct cases.
   Require clean stderr and no new failed rules. Record the existing caption
   failures separately; never report those PDF/UA-2 cases as compliant.
4. Require Windows/Linux CI on the final commit. Review the unchanged 1,662-case
   independent corpus against retained run 39081603694: 1,620 PASS, 24 FAIL and
   18 REFERENCE-DISPUTED. Keep existing failures and tolerances visible, and
   review every changed PDF, raster and verdict.
5. Require exact-tag Python and Rust release workflows. Retain qualification
   evidence beyond CI expiration. Verify public downloads and hashes, then
   replay the output gate through the public packages before announcing release.
