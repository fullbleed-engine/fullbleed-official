# 2.5.24 hidden HTML text release

Target release tag: `v2.5.24`.

1. Retain the published 2.5.23 negative control for issue #78. Use the
   [HTML hidden-element defaults](https://html.spec.whatwg.org/multipage/rendering.html#hidden-elements)
   and explicit visible-content controls as the expected behavior.
2. Run the Rust and Python suites and `tools/smoke_hidden_text.py` against the
   installed candidate wheel. Check default script/style hiding, ordinary
   hidden descendants, author display overrides, display rollback, whitespace,
   lists, tables, captions, preformatted text, fragments, and full documents.
   Retain PDFs, independent text extraction, native previews, PDFium previews,
   and repeat-render comparisons for direct, compiled, fixed, and reflow output.
3. Run the unchanged CSS corpus and compare its PDFs and verdicts with the
   retained 2.5.23 source run `38624093099`. Inspect every changed fixture and
   retain the original failures and disputed references. Do not publish with
   unexplained regressions.
4. Synchronize release metadata. Build/install the final-version wheel,
   regenerate agent artifacts from it, then rebuild and verify the final wheel,
   release metadata, license integrity, and bundled Skill.
5. Require the final source commit's Windows/Linux CI and retain its output.
   Merge normally and tag the same verified source tree.
6. Publish through the existing trusted PyPI and crates.io workflows. Verify
   fresh registry consumers and the public wheel's hidden-text gate. Attach
   retained evidence before describing the fix as released.

The semantic `data-fb-a11y-only` text carrier remains separate from visual text
extraction. Scripts are not executed, and embedded CSS is not applied. This
change does not establish general CSS parity or PDF conformance. Node and .NET
engine pins remain at their separately verified releases.
