# 2.5.11 standard-font preview release

Target release tag: `v2.5.11`.

The published 2.5.10 wheel produced 14 blank default Standard 14 previews with
system fonts hidden in a private Linux mount namespace. All 14 registered-font
controls rendered. Preserve that negative control with the qualification evidence.

1. Reproduce the pinned font programs with `python tools/generate_preview_fonts.py
   --check` using development-only fontTools 4.65.0. Check complete license notices
   in the crate and wheel. No generation tool or font download belongs in runtime.
2. Build and install a wheel. Run `tools/smoke_standard_font_portability.py --out
   target/standard-font-preview`; it checks 68 cases and preserves PDFs, PNGs,
   glyph-cell metadata and hashes. Inspect the Latin, Symbol and Dingbats grids.
3. On Linux, run the same check through `sudo unshare --mount --propagation private`
   with `--mask-system-fonts`. Compare against the ordinary run using `--compare`.
   This may only mask fonts inside the private namespace. Compare the Windows and
   Linux pixel and PDF hashes too. Preserve explicit-font baseline comparisons
   with published 2.5.10 and confirm preview never changes its source PDF.
4. Run focused and complete Python and Rust suites, existing spacing and embedded
   font checks, goldens and packaged-consumer checks. Keep the existing print
   profile gate; this is not a new PDF standards conformance claim.
5. Synchronize Cargo, Python, lockfile and automation metadata. Generate the agent
   artifacts from the installed final-version wheel, rebuild, and check them from
   that final artifact. Validate the bundled Skill and exact-source CI.
6. Merge the reviewed commit and publish through the existing trusted workflows.
   Verify public artifact hashes and fresh consumers before updating release or
   dependent-package claims. Node and .NET releases remain independent.

The bundled fonts are fixed substitutes, not the original proprietary designs.
The unsupported unencoded Symbol `/apple` glyph is documented in the manifest.
Registered/embedded fonts remain authoritative. Unregistered fonts outside the
Standard 14 set can retain their previous viewer/system substitution behavior.
