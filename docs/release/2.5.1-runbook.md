# Fullbleed 2.5.1 release runbook

This patch makes MCP tool output schemas acceptable to strict protocol clients.
It does not change the Rust renderer or add a core runtime dependency. Publish
only from a clean annotated `v2.5.1` tag after the checks below pass.

## Package and contract preparation

Keep Cargo, Python, CI, release defaults, and generated core artifacts at 2.5.1.
The audit crate remains 0.1.3 and the separately versioned MCP adapter remains
0.1.0 for this core release. Previously verified Rust examples may stay pinned
to 2.5.0. The pinned container must be updated to 2.5.1 wheel hashes after those
artifacts are public; do not claim that its earlier 2.5.0 image has this fix.

Build and install the candidate wheel in an isolated environment. Generate
agent artifacts with `tools/generate_agent_contract.py --python PATH --json`,
then rebuild and reinstall the final wheel. Run the generator again with
`--check`. Never hand-edit the generated JSON, CLI reference, or `llms.txt`.

## Required verification

- Run focused MCP and agent-contract Python tests, then the full Python suite.
- Run `tools/smoke_installed_package.py --expected-version 2.5.1 --json` and
  `tools/smoke_mcp_stdio.py --json` with the installed candidate and adapter.
- Install the locked development dependencies in `tools/mcp-client-smoke` and
  run `smoke.mjs` with the candidate Python executable. Retain the official SDK
  result and generated PDF. Keep the failing 2.5.0 reproduction separately.
- Check release metadata, licenses, generated MCP metadata, deterministic
  goldens, CSS status, and the bundled Skill's documented validation workflow.
- Require the repository CI and release matrix for the final source: 15 ABI3
  wheels, all installed-wheel checks, the sdist, Rust MSRV checks, and existing
  print-profile preflight. Inspect the retained logs and artifacts.

The new SDK smoke runs on both Windows and Linux in repository CI. Passing
introspection does not establish compatibility with every MCP client or PDF
standards conformance. Existing release gates and their qualification limits
continue to apply.

## Publication and independent follow-up

Publish only validated artifacts. Keep public PyPI, GitHub, and crates.io
versions and checksums aligned. Verify a fresh public installation with the
official MCP SDK after publication.

Update the optional container's pinned requirements from the public Linux
wheel digests and rerun its checks. Rebuild the Glama entry against the corrected
engine, retain its actual introspection result, and add a directory quality
badge only once that result is verified. The directory submission is not a
substitute for the local and CI interoperability checks.
