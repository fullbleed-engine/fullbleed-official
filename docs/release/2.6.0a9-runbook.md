# Component alpha 9 qualification

Python prerelease: `2.6.0a9`, tag `v2.6.0a9`. Cargo source: `2.6.0-alpha.9`.

This release makes the merged PageBand/PageNumbers API installable without a
source build. Its runtime implementation is the source reviewed in PR #85,
merged as `5394918cc4444960bdd4b1c297a9721f4de14213`. Keep the component API
experimental and ordinary stable installation on 2.5.34.

1. Synchronize Python, Cargo, lockfile and CI versions. Preserve the reviewed
   runtime implementation and unrelated local work. Record the source and
   protected-file hashes used during preparation.
2. Run native tests. Build and install the new-version wheel, generate the agent
   artifacts from that installed runtime, then rebuild and install the final
   wheel. Check generated contracts, component stubs, package contents, release
   metadata, installed behavior, type checking and the bundled Skill.
3. Run focused component tests and the full Python suite on the final installed
   wheel. Retain the PageBand matrix, including rejected inputs, styled-number
   comparisons against literal controls, per-record counts, first/blank-page
   policy, layout/paint failures and source-aware diagnostics. Compare its saved
   PDFs, pixels and rejection payloads with the qualified implementation.
4. Preserve the earlier running-reflow, page-furniture, page-margin geometry and
   deferred-running-layout output. Recreate Northstar and Common Ground through
   both authoring paths, the accessible guide in both PDF/UA profiles, and the
   new field-notes report in ordinary PDF, PDF/UA-1 and PDF/UA-2. Verify text,
   pixels, structure, deterministic bytes, and styled/unstyled HTML exports.
   Retain independent PDF/UA evidence for the exact saved outputs. Reuse a
   validator result only when both its successful report and the input PDF have
   verified matching hashes; otherwise validate the new file.
5. Require exact-source Windows/Linux CI and inspect its saved matrices and
   standalone starter archives. Preserve existing snapshots, references and
   tolerances. Retain the complete independent CSS comparison with its actual
   verdicts and scores. Compare source provenance and every saved output with
   the reviewed baseline; its 25 failures and 18 disputed references must remain
   visible and must not be described as a passing conformance test.
6. Verify the exact annotated tag and release workflow. Check all public wheels
   and the source archive, then recreate the page-band matrix and representative
   authoring/accessible showcases in a fresh public installation. Check ordinary
   pip resolution still selects stable before publishing the GitHub prerelease.
7. Attach checksums, reports and a reproducible source download. Publish a
   current guide and runnable page-band example, preserve historical downloads,
   and verify the public package, links and visible page. Merge the qualified
   release metadata into the default branch and verify its resulting CI.

PageBand bounds are deliberately conservative, and unsupported content must
fail explicitly. Named/facing-page band variants and arbitrary styling of
generated-number pseudo children are outside this API. Streaming output is not
atomic. Changed bindings reflow running content. HTML export uses one header
and footer with explicit page placeholders; static Bootstrap adds no JavaScript.
Saved-specimen checks do not prove accessibility for arbitrary documents or
human assistive-technology usability. Dedicated PDF/VT validation is not configured.
