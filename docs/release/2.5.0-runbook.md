# Fullbleed 2.5.0 release runbook

This release adds CLI watch mode and tested onboarding examples. It makes no
new rendering-conformance or performance claim. Publish only from a clean,
annotated `v2.5.0` tag after the checks below pass.

## Version and package contract

- Cargo, Python, CI, release defaults, and generated core artifacts report 2.5.0.
- `fullbleed_audit_contract` stays 0.1.3; `fullbleed-mcp` stays 0.1.0 and accepts `fullbleed>=2.3.0,<3`.
- Keep 15 `cp310-abi3` platform wheels, CPython 3.10–3.14, Rust MSRV 1.85, and no third-party Python runtime dependencies.
- Historical notebooks and previously retained evidence may remain pinned to the versions they actually tested.

## Build and local verification

Use an isolated Python environment. Build a wheel, install it, regenerate the
agent artifacts from that installed runtime, then rebuild **and reinstall**
the wheel so its packaged contract includes those final generated artifacts.
Never hand-edit the generated JSON, CLI reference, or `llms.txt`.

```powershell
python build_backend/fullbleed_build_backend.py wheel --out target/release-2.5.0/dist
python -m pip install --force-reinstall target/release-2.5.0/dist/fullbleed-2.5.0-cp310-abi3-win_amd64.whl
python tools/generate_agent_contract.py --python python --json
python build_backend/fullbleed_build_backend.py wheel --out target/release-2.5.0/dist
python -m pip install --force-reinstall target/release-2.5.0/dist/fullbleed-2.5.0-cp310-abi3-win_amd64.whl
python build_backend/fullbleed_build_backend.py sdist --out target/release-2.5.0/dist
python tools/generate_agent_contract.py --python python --check --json
python tools/generate_mcp_server_json.py --check --json
python tools/check_release_metadata.py --expected-version 2.5.0 --json
python tools/check_license_integrity.py --json
$env:FULLBLEED_TEST_INSTALLED_NATIVE = "1"
python -m pytest tests/test_fullbleed_cli_watch.py tests/test_fullbleed_agent_contract.py -q
python -m pytest -q
python tools/smoke_installed_package.py --expected-version 2.5.0 --json
python -I tools/smoke_render_watch.py --out target/release-2.5.0/watch-local
python goldens/run_golden_suite.py --python python verify
python tools/generate_css_parity_status.py --check --json
cargo fmt --all --check
cargo test --locked
cargo test --locked --features python,svg_raster
cargo check --locked --all-targets --all-features
python -m twine check target/release-2.5.0/dist/*
```

Run the bundled Skill validator and the `gh skill publish --dry-run` check
described in `docs/agent-discovery.md`. Retain logs and test counts. The final
clean commit must pass `python tools/check_release_worktree.py --json`.

## CI and print-profile gates

The normal CI workflow must pass at the final release commit. It covers Rust
on Windows/Linux, installed Python packages, CPython compatibility, golden
outputs, and real-process watch behavior on Windows/Linux.

Run `release.yml` with `publish_pypi=false` against the candidate branch before
tagging if package-matrix validation is still needed. Its release gates must
pass for the exact source being published:

- Required print-profile preflight: 17 profiles, five VT source scenarios, 21 corruption controls, rewrite positive control, and deterministic replay. It uses veraPDF, pdf_oxide, and a separate pypdf parser. Retain the `print-profile-release-evidence` artifact.
- Source, license, worktree, installed contract, full Python, Rust, packaging, and fresh-consumer MSRV checks.
- All 15 wheels and the sdist; 19 installed-wheel checks; distribution metadata and ABI3 tags.
- Real-process watch checks on each native Windows and macOS release wheel. Retain `release-watch-*` artifacts and compare the final PDF hashes with the Linux CI specimen.

Windows smoke harnesses terminate their child process explicitly; they do not
verify physical Ctrl-C delivery. Unit tests cover the interrupt handler, and
POSIX smoke tests verify SIGINT exit 130. The watcher does not turn failed
renders into successful delivery gates.

The optional dedicated PDF/VT validator configuration and its claim boundaries
are documented in the [2.4.0 runbook](2.4.0-runbook.md#optional-dedicated-pdfvt-preflight).
It remains an additional gate when configured. Passing the mandatory writer
contract checks does not establish exhaustive ISO PDF/VT-1 conformance.

## Publish and verify

1. Merge the validated release preparation, retain evidence for its exact source, and create the annotated `v2.5.0` tag. Do not move an existing release tag.
2. Let the tag-triggered Release workflow finish. Download its `release-dists`, print-profile evidence, Cargo evidence, and native watch artifacts; preserve them beyond CI retention.
3. Dispatch `publish-crates.yml` for `v2.5.0` with `publish=true` and `release.yml` at `v2.5.0` with `publish_pypi=true`. If trusted publishing is unavailable, use an already authorized publication credential only for the validated distribution set. Never include credentials in logs or source.
4. Publish the GitHub release from `ReleaseNotes.MD` with all distributions, a SHA-256 manifest, and retained engineering evidence.
5. Verify PyPI and crates.io versions, MIT metadata, unyanked status, exact public artifact hashes, and matching tagged source. Install the public wheel in a fresh environment and run version, doctor, compliance, installed-package, generated-contract, and real-process watch checks.
6. Update the public docs and site only with commands supported by that verified public release. Record URLs and verification results without claiming downloads or adoption that have not been measured.
