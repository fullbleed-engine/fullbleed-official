# 2.5.32: oversized table cells and compiled reflow

Release tag: `v2.5.32`.

A single rich cell taller than a page could stall behind repeated headers or be
painted outside the page. Logical cell splitting now continues paragraphs,
lists and plain lines while retaining column widths, ending decoration and one
logical TH/TD. Default baseline and top alignment use this path. Ordinary rows
that fit a fresh page still move intact. See
[issue #99](https://github.com/fullbleed-engine/fullbleed-official/issues/99).

The output checks also exposed compiled-reflow failures: cached pages could
lose embedded glyph mappings on replay, and synthesized-bold text could display
the first recipient while its searchable text named another. Font seeds are now
restored on first use without moving their PDF objects. Replay state is keyed by
the actual batch values. A changed value painted as independent outlines falls
back to layout; it cannot reuse a patch of only the invisible text companion.
Changed table values also return to layout, because cell text can change column
widths and the positions of other cells. This guard covers presentation tables
as well as semantic tables and does not depend on accessibility tags.

## Retained controls

- Public 2.5.31 times out on the original twelve-paragraph repeated-header input.
  Its header-removal and tall-page controls are retained with source hashes.
- Published 2.6.0a5 terminates but clips this default-baseline input. Passing
  PDF/UA checks did not detect the missing visible lines. It is not a qualified
  fix for this case.
- Public 2.5.31 also draws "Ada" for both records in a synthetic "Ada"/"Bea"
  batch although extraction returns the two names. Separate single-record PDFs
  provide the independent expected pixels. Retain both versions of the evidence.
- Its regular-text table control also places the second column using the first
  record's cell widths. The corrected batch matches both separate records in
  untagged and PDF/UA-1 output. The 180-case table gate now retains separate
  single-record references and compares every mode's page pixels against them.
- A 320pt-wide three-column control overflows even on an unsplit 900pt-tall page
  in public 2.5.31. Its intrinsic minimum columns exceed the available width.
  The pagination fixture uses a 420pt page; the narrow failed control remains
  retained as a distinct width limitation.
- Rejected candidates and their logs remain retained. One passed all 120 external
  PDF/UA checks but failed visual and replay checks; another changed object order.
  A subsequent candidate fixed those cases but retained stale visible recipient
  outlines. Another passed the 240- and 180-case gates but failed independent
  per-record column geometry checks. None qualifies for publication.

## Publication gates

1. Require focused installed-wheel tests and both full native feature sets.
   Build and install the optimized versioned wheel, generate the agent artifacts
   from that runtime, then rebuild and verify the final packaged wheel. Check
   release metadata, the bundled Skill and installed-package behavior.
2. Require the full Python suite and unchanged golden documents.
3. Retain all 240 oversized-table PDFs, inputs, glyph bounds, ink checks and
   previews. Require one copy of every body marker per record, no empty/header-only
   page, one logical table cell per authored cell, preserved header relationships,
   independent tag/untagged pixel equality and repeated-render determinism.
4. Require the existing 180-case table-tagging gate and independent PDF/UA-1 and
   PDF/UA-2 validation for the 120 new profiled cases. Record the separate caption
   failures in issue #98 without weakening or suppressing the validator rules.
5. Compare cached, changed and fresh batches against independently rendered
   single-record PDFs. Cover two fonts, later-page font use, regular and
   synthesized-bold text, and throughput/compact compression. Extraction alone
   does not prove that the visible recipient is correct. Also compare auto-sized
   semantic and presentation tables with short and long values against separate
   single-record layouts.
6. Require Windows/Linux CI and review the unchanged 1,662-case corpus against
   the retained 2.5.31 baseline, including every changed PDF, raster and verdict.
   Keep existing failures and tolerances visible.
7. Require exact-tag Python and Rust publishing workflows. Retain qualification
   evidence beyond CI expiration and verify public package hashes and output
   before announcing availability.

## Scope

Oversized rowspans and middle/bottom-aligned rich cells retain existing fallback
behavior. Caption containment in issue #98 remains unresolved. The experimental
component alpha needs a separately built and qualified native update. No claim
of general PDF/UA conformance, browser parity or performance follows from these
focused checks.
