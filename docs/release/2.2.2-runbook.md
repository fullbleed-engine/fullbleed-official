# Fullbleed 2.2.2 Release Runbook

Status: final

This runbook validates and publishes the parity, flow/reflow, Unicode bidi, audit-contract, and
compiled coordinate-state improvements in `v2.2.2`. Release only from the exact annotated tag;
registry artifacts are immutable.

## Release Contract

- `Cargo.toml`, `Cargo.lock`, `pyproject.toml`, and CI report `2.2.2`.
- `fullbleed_audit_contract` reports `0.1.3`, and the root dependency requires that exact release.
- `subsetter 0.2.6`, `rustc-hash 2.1.3`, and `unicode-bidi 0.3.18` are disclosed in Cargo
  metadata and the generated CycloneDX SBOM.
- Python build requirements, runtime requirements, and the `api` compatibility extra remain empty.
- Wheels retain the `cp310-abi3` tag and cover standard CPython 3.10 through 3.14 on all 15
  declared platforms.
- Both shipped Rust crates and the Python distribution remain MIT licensed.
- Signed Q32.32 fixed-point layout geometry remains authoritative.
- Performance claims preserve the distinct-record, fixed-geometry binding boundary.
- Rust debug test-harness threads use a 4 MiB stack in CI and release workflows on every OS.

## Clean-Checkout Validation

Run from the proposed release commit in a clean worktree:

```powershell
python tools\check_release_metadata.py --expected-version 2.2.2 --json
python tools\check_license_integrity.py --json
cargo fmt --all --check
$env:RUST_MIN_STACK = "4194304"
cargo test --locked
cargo test --locked --features python,svg_raster
cargo check --locked --all-targets --all-features
cargo tree -e normal --all-features
cargo tree -e build --all-features
python build_backend\fullbleed_build_backend.py wheel --out target\validate-wheel-2.2.2
python -m pip install --force-reinstall target\validate-wheel-2.2.2\*.whl
python -m pytest -q
python tools\generate_css_parity_status.py --check --json
python tools\check_release_worktree.py --json
```

The expected normal dependency graph is:

```text
fullbleed 2.2.2
|-- fullbleed_audit_contract 0.1.3
|-- subsetter 0.2.6
|   `-- rustc-hash 2.1.3
`-- unicode-bidi 0.3.18
```

The Windows extension must depend on `python3.dll`, never a versioned `python3XY.dll`. Linux and
macOS extensions resolve CPython symbols from the loading interpreter.

## Parity and Variable-Data Gates

The pinned official Wheel265 parity run must complete with 1,642 comparator passes, zero
implementation failures, and 20 explicitly reference-disputed cases. Preserve the complete report
and invocation identifier in release evidence; do not convert disputed references into engine
passes.

```powershell
python tools\benchmark_fullbleed_vdp.py --records 100000 --repeats 5 `
  --output target\benchmarks\fullbleed-vdp-100000-2.2.2.pdf
```

Require 100,000 distinct verified record values, deterministic buffer/file hashes, and at least
100,000 direct-file pages/s. Transformed or clipped binding fixtures must also match the ordinary
renderer under external Poppler rasterization.

## Packaged Rust and MSRV Gates

```powershell
rustup toolchain install 1.85.0 --profile minimal
rustup run 1.85.0 python tools\smoke_crates_consumer.py --expected-version 2.2.2 --json
cargo publish --locked --dry-run --manifest-path crates\fullbleed_audit_contract\Cargo.toml
cargo publish --locked --dry-run
```

Publish `fullbleed_audit_contract 0.1.3` first. Wait for crates.io index propagation, then package
and publish `fullbleed 2.2.2` from the same immutable source.

## Python Distribution Gate

```powershell
python build_backend\fullbleed_build_backend.py wheel --out target\release-2.2.2\dist
python build_backend\fullbleed_build_backend.py sdist --out target\release-2.2.2\dist
```

Verify the wheel contains the Stable ABI extension, `fullbleed/_abi.py`, licenses, runtime
specifications, and CycloneDX SBOM. The release workflow builds and installs:

- manylinux2014: x86-64, x86, ARM64, ARMv7, s390x, ppc64le;
- musllinux 1.2: x86-64, x86, ARM64, ARMv7;
- Windows: x86-64, x86, ARM64;
- macOS: Intel and Apple silicon.

The x86-64 manylinux wheel is additionally installed under Python 3.10, 3.11, 3.12, 3.13, and
3.14.

## Tag and Publish

1. Confirm every local gate passes and commit the intended release source without local `tmp/`
   evidence.
2. Push the release commit to `origin/master`.
3. Create and push the annotated tag:

   ```powershell
   git tag -a v2.2.2 -m "Fullbleed 2.2.2"
   git push origin v2.2.2
   ```

4. Let the tag-triggered `Release` workflow validate and build the complete distribution set.
5. Dispatch `publish-crates.yml` for `v2.2.2` with `publish=true`.
6. Publish the exact validated 15-wheel plus sdist set to PyPI through trusted publishing or the
   scoped project token.
7. Create the public GitHub `v2.2.2` release from `ReleaseNotes.MD` and attach those same immutable
   Python distributions plus a SHA-256 manifest.

## Post-Publish Checks

```powershell
cargo info fullbleed_audit_contract@0.1.3
cargo info fullbleed@2.2.2
python -m pip install --no-cache-dir fullbleed==2.2.2
fullbleed capabilities --json
fullbleed doctor --strict --json
```

Confirm crates.io reports MIT and not-yanked metadata, PyPI exposes all 16 expected files, the
GitHub release assets match the validated workflow artifacts, and a clean Python environment can
import the compiled binding API and render distinct records. Corrections require a new version.
