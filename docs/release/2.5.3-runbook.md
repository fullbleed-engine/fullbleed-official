# Fullbleed 2.5.3 release runbook

This patch prevents false passes from invalid reproducibility baselines, detects
asset-lock presence changes, and prevents a check from overwriting its baseline.
Publish from a clean annotated `v2.5.3` tag after the checks below pass.

## Build and verify

Keep Python, Cargo, the CI smoke version, release defaults, and generated agent
artifacts synchronized at 2.5.3. The audit crate remains 0.1.3 and the optional MCP
adapter remains 0.1.1. Existing example and container pins retain the releases
against which those artifacts were verified.

Build and install a wheel in an isolated environment. Run
`tools/generate_agent_contract.py --python PATH --json`, rebuild and reinstall the
final wheel, then run the generator with `--check`. Never hand-edit generated
contracts. Build the source distribution from the same final source.

- Run `tests/test_fullbleed_cli_repro.py`, then the full Python suite with
  `FULLBLEED_TEST_INSTALLED_NATIVE=1`.
- Run `python -I tools/smoke_repro_check.py --out target/repro-smoke` against the
  installed wheel. Retain every CLI result, changed PDF, and preview. Require
  unchanged/relocated/recovered projects to pass and malformed records, changed
  inputs/output, missing files, lock changes, and conflicting paths to fail.
- Run installed-package smoke, generated-contract checks, deterministic goldens,
  CSS status, license integrity, release metadata checks, and the bundled Skill
  validator described in the contributor workflow.
- Require the final PR's Windows and Linux CI checks, including the real-process
  reproducibility gate. Inspect its retained artifacts before release.
- Require the complete release workflow and its existing platform-wheel,
  installed-package, Rust, source-distribution, and print-profile checks.

Valid old v1 records must remain usable. The record schema's required hashes and
known field types are validated; unknown additive metadata remains accepted.
Separate record/check paths remain supported on both pass and failure.

## Publish and check public artifacts

Publish through the configured PyPI trusted publisher and crates.io workflow.
Retain the exact source tag, CI evidence, registry metadata, and artifact hashes.
Verify the public distributions match the release artifacts. Install the public
wheel into a fresh environment and rerun the reproducibility smoke before claiming
the fix is available to users.

This release does not change rendering algorithms. Hash equality covers only the
retained fixtures. The existing dedicated PDF/VT validator remains optional and
unconfigured; do not turn its skipped result into a conformance claim.
