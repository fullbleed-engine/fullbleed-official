# Component alpha 12 qualification

Python prerelease: `2.6.0a12`; Cargo source: `2.6.0-alpha.12`; tag: `v2.6.0a12`.

This release packages the component namespace and complete-document migration
from [PR #119](https://github.com/fullbleed-engine/fullbleed-official/pull/119).
The API remains alpha. Preserve both earlier authoring paths and all existing
qualification workflows. No new core dependency is required.

1. Confirm registry/tag availability, source identity and version synchronization.
   Preserve unrelated local files. Keep dated examples and previously published
   source kits pinned to their original versions.
2. Build and install the new-version wheel. Generate agent artifacts from that
   installed runtime, rebuild the final wheel, and check generated artifacts,
   package contents, release metadata, installed behavior and the bundled Skill.
3. Run focused component tests and the full Python suite. Run both namespaces
   through `tools/smoke_component_typing.py` and
   `tools/smoke_component_editor.py --namespace fullbleed.components` plus the
   editor's original namespace. Retain the diagnostic and LSP receipts.
4. Run the complete-document and mixed-node migration checks. Retain all PDFs,
   HTML/CSS, independent previews, metadata, geometry and repeat-byte receipts.
   Compare the complete-document output with the qualified implementation and
   public alpha 11 baseline. Run the installed guide/agent quickstart, page-band
   examples and paired showcases. Keep all existing release browser, profile,
   native and integration gates. Do not infer arbitrary-document conformance
   or human accessibility usability from saved specimens.
   Run `examples/web_frameworks/check_examples.py` with the installed release
   wheel and the optional `requirements-check.txt` tools. Review its saved
   preview against the exact-version sample, then build the downloadable starter
   from the committed candidate. Check all three actual HTTP server responses;
   package version changes must not silently select an older preview.
5. Verify exact-source Windows/Linux CI, public namespace artifacts and postmerge
   implementation CI. Compare the independent CSS corpus with alpha 11 without
   changing inputs, references, comparator or thresholds. Preserve its failing
   conclusion: 1,623 PASS, 21 FAIL and 18 REFERENCE-DISPUTED, unless new evidence
   is reviewed and explained. Retain every verdict and PDF/PNG hash comparison.
6. Publish an immutable annotated tag only after qualification. Let the release
   workflow build and check every wheel and the source archive before OIDC
   publication. Verify all public distribution hashes against the qualified
   workflow outputs, install into a fresh environment and run the new import,
   migration and HTML-export examples. Verify ordinary stable resolution.
7. Build a standalone migration source ZIP with the two authoring functions,
   optional independent verifier, licenses and explicit package pins. Test it
   first without optional tools, then with its verifier, from a fresh public
   installation. Publish a GitHub prerelease with that source kit and retained
   evidence. Update current documentation after public verification, including
   installation pins and the namespace/migration stabilization gate. Keep the
   kit-composition and independent-author-feedback gates open. Merge the verified
   release metadata and check the resulting default-branch CI.

No new JavaScript/.NET API coverage, browser-print equivalence, arbitrary CSS
parity, paid-validator result or independent adoption is implied by this release.
