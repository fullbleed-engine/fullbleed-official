# Stable 2.5.34: page furniture and running record values

The release tag is `v2.5.34`.

This candidate backports two engine corrections from the component authoring
branch onto stable 2.5.33. It does not include that branch's joint margin sizing,
deferred layout marker, or proposed PageBand/PageNumbers constructors.

## Scope

- Mark generated page-margin text, running content and decoration as artifacts
  without suppressing real body tags. Track publication in issue #103.
- Reflow documents with running content when bindings change so a shared body
  value cannot leave a previous record's value inside a captured Form. Track
  publication in issue #104. Static running headers also reduce cache reuse when
  body values change; no performance improvement is claimed.

## Required evidence

Keep candidate and public-package evidence separate under
`target/growth/stable-page-furniture-20261019/`.

1. Verify the retained public 2.5.33 wheel and native library. Its calibrated
   running-value matrix has 30 failing cases and 24 passing controls. Retain the
   older 120-case page-furniture negative controls and their original PDF hashes.
2. Run formatting, focused native tests and the full native suite. The header
   regression must inspect the captured Form text, not only page-local strings.
3. Build and install the candidate wheel. Regenerate contracts from that runtime,
   rebuild/install the final wheel, then check metadata, installed behavior,
   license and bundled Skill. Keep optional readers/validators out of runtime
   dependencies.
4. Run focused and full Python tests plus golden outputs. Preserve the existing
   user-owned file changes byte for byte.
5. Inspect all 120 page-furniture PDFs and 54 running-value PDFs. Compare each
   batch record's text and independent raster output with separately rendered
   records. Check deterministic bytes and body structure. Page-furniture pixels
   must match the stable baseline; existing raw CSS geometry is unchanged.
6. Run veraPDF separately on all 116 PDF/UA-1 and PDF/UA-2 fixtures with clean
   stderr. Record validator/version and exact PDF hashes. These automated results
   are fixture-specific and do not establish human assistive-technology usability.
7. Review exact-head Windows/Linux CI artifacts and the independent CSS corpus.
   Retain every raw verdict, reference and threshold. Existing failures remain
   visible; source correctness is not a blanket CSS parity claim.
8. After merge and release workflow gates, publish using existing OIDC. Verify
   fresh public Python and Rust consumers and registry checksums/source identity
   before closing #103 or #104 or claiming a published correction.

The reviewed 2.6.0a7 private source candidate is a useful regression reference;
it is not evidence that this stable wheel has been built or published. Gate
statuses and actual counts belong to their retained receipts.
