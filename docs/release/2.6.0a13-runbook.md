# Rich-inline initial alpha 13 qualification

Python prerelease: `2.6.0a13`; Cargo source: `2.6.0-alpha.13`; tag: `v2.6.0a13`.

This release packages [PR #121](https://github.com/fullbleed-engine/fullbleed-official/pull/121).
The component API remains alpha, with its independent-kit and author-feedback
gates open. Preserve existing authoring paths and qualification workflows.

1. Verify registry/tag availability, exact source identity, version consistency
   and the implementation's default-branch CI. Preserve unrelated local files
   and previously published, version-pinned kits and evidence.
2. Build and install the new-version wheel. Generate agent artifacts from that
   runtime, rebuild the final wheel, then check generated artifacts, installed
   behavior, package contents, metadata and the bundled versionless Skill.
3. Run the rich-first-letter regression and the existing floating-initial,
   inline line-height, wrapping and sizing tests against the installed wheel.
   Run the full Python suite. Retain the 22-case direct/compiled/reflow/native
   output and reading-order receipts, and compare the 66 PDFs and 56 previews
   with the visually reviewed implementation. Review any changed output.
4. Retain final-source Linux/Windows CI, including component typing/editor,
   migration, styled/unstyled HTML, browser, profile and integration gates.
   Check the paired document showcases and complete-document migration with
   the installed package. For web-framework examples, generate and review a
   new `examples/web_frameworks/static/invoice-2.6.0a13.png` explicitly before
   running `examples/web_frameworks/check_examples.py` with optional check
   dependencies. Require that exact sample; do not overwrite the shared or
   older version previews. Check all three actual local HTTP server responses.
5. Compare the complete independent CSS corpus with qualified alpha 12. Keep
   its inputs, references, comparator and thresholds unchanged. Retain all
   1,662 verdicts and 7,437 PDF/PNG hashes, and preserve the failing conclusion
   (1,623 PASS, 21 FAIL, 18 REFERENCE-DISPUTED) unless reviewed new evidence
   explains a change. Do not claim complete CSS or accessibility conformance.
6. After qualification, publish an immutable annotated tag. The release
   workflow must validate every wheel and source archive before OIDC PyPI
   publication. Compare all public distribution hashes with workflow outputs,
   install the public wheel into a fresh environment and run the rich-initial
   checks and component/HTML-export examples. Verify ordinary stable resolution.
7. Publish the GitHub prerelease with scoped release notes, retained rendering
   and corpus evidence, and hashes. Update current documentation after public
   verification, then merge the qualified release metadata and check default-
   branch CI. Keep historical examples and standalone kits pinned as published.

Generated-content initials, decorated inline ancestors, vertical text and the
separate `initial-letter` sizing model are outside the new gate. Dedicated
PDF/VT validation remains unavailable. No language-binding expansion, core
dependency, stable-component graduation or independent-adoption claim is made.
