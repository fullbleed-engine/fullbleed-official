# 2.6.0a1: opt-in Python component authoring alpha

Release tag: `v2.6.0a1`. Python distribution version: `2.6.0a1`.
Cargo source version: `2.6.0-alpha.1`.

The alpha makes the experimental component API available through an explicit
pip installation. It includes the static Bootstrap 5.0.0 kit, styled/unstyled
HTML export, immutable styles, required/optional part bindings and deliberate
child forwarding. The [Bootstrap guide](../component-bootstrap.md) and
[component guide](../../examples/component_recipes/README.md) document the API.
The earlier GitHub preview downloads remain pinned to their original commits.

## Version and channel policy

Fullbleed publishes canonical three-part Python versions with optional `aN`,
`bN` or `rcN` suffixes. Cargo's corresponding suffixes are `-alpha.N`, `-beta.N`
and `-rc.N`. The release checker validates this mapping and rejects mismatched
manifests, lockfiles, CI versions and requested tags. This is the project's
release policy, not a general version parser. See the
[Python version specification](https://packaging.python.org/en/latest/specifications/version-specifiers/#pre-releases)
and [Cargo's version field](https://doc.rust-lang.org/cargo/reference/manifest.html#the-version-field).

Install the alpha explicitly with
`python -m pip install --pre "fullbleed==2.6.0a1"` in a virtual environment.
Normal stable resolution must continue to select the existing final release;
verify that against the real index after publication. The crate manifest shares
the source version, but this runbook does not publish a Rust alpha or update the
separately versioned JavaScript/.NET integrations.

## Required evidence

1. Build and install a candidate wheel. Generate agent artifacts from that
   installed runtime, then rebuild and reinstall the final wheel. Check the
   packaged and runtime versions, generated stubs, license integrity, release
   metadata and bundled Skill. Verify the wheel filename, dist-info directory,
   METADATA and sdist all carry the canonical Python version.
2. Run the release-version failure controls, focused authoring tests and full
   Python suite with the installed extension. Execute the README's first alpha
   document from an otherwise empty directory. Inspect the resulting PDF and
   verify styled/unstyled HTML exports.
3. Run installed-wheel component recipes, part-forwarding controls and Bootstrap
   catalog checks, with independent PDF reading and raster checks. Retain
   metadata, text, geometry, repeatability and glyph results. Run mypy and
   Pyright consumer/completion checks. The release workflow retains this evidence
   in `release-components`; normal Windows/Linux CI retains component outputs too.
4. Build from a clean, committed checkout using the full Release pipeline before
   publishing. Keep source validation, Rust/MSRV checks, all 15 wheel targets,
   container/native installation checks and sdist/metadata validation enabled.
   The Cargo consumer check receives the SemVer version; Python smoke checks
   receive the canonical Python version.
5. Inspect final distributions against the exact source commit and test the
   actual downloaded platform wheel. Publish using the existing PyPI trusted
   publisher only after its dependency gates pass. A successful build alone is
   not evidence of registry publication.
6. Verify PyPI has the intended wheel set and sdist, install the exact public
   alpha into a fresh environment, run the first document, and verify the
   default pip resolver still selects the stable version. Create the matching
   GitHub release as a prerelease, without replacing its latest stable release.
7. Update the public guide to the verified alpha install path and distribute the
   same source examples. Retain older pinned preview links for reproducibility.

## Scope and outstanding work

The API stays in `fullbleed.ui.experimental`. Independent author feedback,
stable API promotion, dynamic token/part completion and other language surfaces
remain open. Static component coverage does not establish full Bootstrap CSS,
responsive browser or accessibility parity. The corpus preceding this alpha has
1,619 PASS, 25 FAIL and 18 REFERENCE-DISPUTED results; retain the alpha's own
corpus comparison before making a regression claim.

The dedicated PDF/VT validator is unconfigured. Profile preflight remains
required, and its success does not replace the missing dedicated validation.
This runbook describes the candidate and required gates; publication is proven
only by the registry and retained release evidence.
