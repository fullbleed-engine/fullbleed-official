# 2.5.29: isolated groups in finalized-PDF previews

Release tag: `v2.5.29`.

The JavaScript upgrade checks exposed a difference between two preview paths.
The layout display list and PDF output correctly composited overlapping SVG
shapes at group opacity. Reading that PDF back into the native preview renderer
instead applied the group alpha to each member, making overlaps too opaque.
The same defect affected reused SVG symbols with opacity.

For isolated PDF transparency groups, the reader now resets member alpha and
uses the existing isolated-form raster surface. The group's nonstroking alpha
is applied once to its completed surface. Soft-masked groups retain their
existing masked-form path. This follows the isolated-group behavior described
in [ISO 32000-1 section 11.6.6](https://developer.adobe.com/document-services/docs/assets/35e4369068f86065372c18787171a17e/PDF_ISO_32000-1.pdf);
it does not add general nonisolated or knockout
group support or change the PDF writer.

## Evidence and gates

1. Retain the public 2.5.28 negative control. Its PDFium output is correct but
   16 of 810 SVG checks fail for finalized previews. The 54 source cases, explicit
   RGB expectations, and tolerance remain unchanged.
2. Build and install a candidate wheel. Run `tools/smoke_svg_styles.py --out
   target/svg-styles`, including vector, form and raster-fallback paths; direct,
   compiled, fixed-binding and reflow output; repeated PDFs and both preview
   paths. Compare every retained PDF and image with the public baseline.
3. Run the full Python and native suites. Six focused native regressions cover
   overlap, member alpha, stroked members, nested groups, inherited paint,
   clipping, transforms and caller-state restoration. Windows and Linux CI must
   inspect installed output and retain the saved-PDF PNGs.
4. Build the versioned wheel, regenerate agent artifacts from that installed
   runtime, rebuild and check the final wheel, metadata, bundled Skill and
   installed-package behavior. Do not hand-edit generated contracts.
5. Publish only after the exact-tag release and crates.io gates pass. Verify
   public Python and Rust downloads, their hashes and the same opacity cases.
   Retain reports and outputs with the release beyond CI artifact expiration.

The existing CSS corpus result for 2.5.28 remains historical evidence, including
its 24 failed and 18 disputed cases; this focused preview correction is not a
fresh full-corpus result. Dedicated PDF/VT validation remains unconfigured. No
standards conformance or full browser-rendering parity is claimed.
