## Required release evidence

1. Retain the current published 2.5.37 runtime as a negative control. Run the
   new quotation scenarios against it and record the missing or incorrect marks.
2. Build and install the candidate wheel, regenerate all agent artifacts from
   that installed runtime, then build and reinstall the final wheel and sdist.
   Keep Python, Cargo, generated artifacts, CI metadata and release versions
   synchronized. Preserve the dependency-free runtime/build boundary.
3. Run focused quotation and counter tests, native unit/documentation tests,
   the full stable Python suite, installed-package smoke, generated-contract
   checks, release metadata, package-description checks, license integrity and
   the bundled Skill validator.
4. Independently inspect text and page counts from all saved quotation fixtures,
   including ordinary, compiled, repeated and reflowing PDF outputs. Review
   representative page images. Retain representative ordinary-document controls
   to detect unintended rendering changes. Record bounded CPU and elapsed-time
   comparisons without inferring a general performance claim.
5. Require exact-source Windows/Linux CI. Run and retain the stable candidate's
   full pinned CSS corpus with unchanged inputs, references and thresholds;
   compare it with the qualified stable predecessor, not the development branch.
   Preserve all failures and disputed-reference verdicts. A failed all-pass gate
   stays failed. The dedicated PDF/VT validator may remain unavailable; do not
   claim new conformance from internal checks.
6. Publish only after the checks and any regression review are complete. Use
   the existing release workflows; verify all distribution descriptions before
   upload, registry metadata/checksums, and fresh public Python/Rust consumers.

The component API remains on its separate alpha channel. These tests establish
the bounded quotation behavior and regression results, not full browser parity,
broader accessibility or conformance, or a throughput improvement.
