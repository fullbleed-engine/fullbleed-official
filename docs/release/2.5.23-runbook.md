# 2.5.23 font-selected text-decoration thickness release

Target release tag: `v2.5.23`.

1. Retain the published 2.5.22 negative control and the independent Chrome
   print reproduction with the same explicit Noto Sans font. The expected
   thickness comes from the font's OpenType `post` table and the
   [CSS Text Decoration definition](https://www.w3.org/TR/css-text-decor-4/#text-decoration-thickness-property).
2. Run the Rust and Python suites and the installed text-decoration gate.
   Its 100 cases cover three individual line decorations and their combination
   through direct, compiled, fixed-binding, and both reflow compression modes.
   Check font-native scaling, the first available family, missing/zero metrics,
   the existing minimum width, explicit-length controls, deterministic replay,
   independent PDF stroke widths, and native/finalized/PDFium previews.
3. Run the complete unchanged 1,662-fixture source corpus. Compare every PDF
   hash and verdict with the retained 2.5.22 source run `37890170909`, whose
   PDFs also match the published-wheel run `38600917475`. Review all changes;
   retain failures, disputed references, and the original gate result. Do not
   merge or publish with unexplained regressions.
4. Synchronize release versions, build/install the final-version wheel, and
   generate agent artifacts from that installed wheel. Rebuild and verify the
   final wheel, release metadata, license integrity, and bundled Skill.
5. Require Windows/Linux CI on the final release-preparation commit and retain
   the exact corpus source identity. Merge normally and tag the verified tree.
6. Publish through the existing trusted PyPI and crates.io workflows. Verify
   fresh registry consumers, rerun the decoration gate on the public wheel,
   and retain downloadable evidence before describing this as released.

This change selects the thickness of HTML text decorations using the existing
line-placement rules. It does not establish complete browser layout. No PDF accessibility or
conformance claim follows from these checks. Node and .NET engine pins remain
at their separately verified releases.
