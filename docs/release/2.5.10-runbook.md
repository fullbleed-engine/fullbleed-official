# 2.5.10 inline intrinsic sizing release

Target release tag: `v2.5.10`.

This corrects a regression found while validating the JavaScript binding against
its existing designed invoice/report fixtures. Keep that npm candidate in draft
until it uses the independently verified core correction.

1. Run the Rust tests for intrinsic word spacing and layout-unit rounding. Both
   fail without the correction. Run the complete default and Python/SVG suites.
2. Build and install a wheel. Check the six specimens in
   `tools/smoke_inline_sizing.py`, and retain public 2.5.9 as a negative control.
   Widely tracked text can acquire extra extraction spaces; preserve character
   order and check actual glyph positions. All labels must remain on one line
   when the available width exceeds their full content width.
3. Run the existing 48-case inline wrapping check against that wheel. The
   original overlap correction must remain intact across direct and compiled
   rendering modes. Run the full Python suite, CSS fixtures, goldens, designed
   documents, and the installed/packaged-consumer checks.
4. Render the JavaScript invoice and three-page report using the same explicit
   bundled fonts and sources. Review footers, tracked labels, totals, and page
   geometry against the prior releases. Preserve the original failing candidate
   and its existing font-verification evidence.
5. Synchronize release metadata and regenerate the agent contract, CLI schema,
   and llms.txt from the installed wheel. Rebuild the final wheel and check those
   generated artifacts against its installed runtime. Validate the bundled Skill.
6. Require exact-source CI, preserve platform-specific preview limits, and merge
   with the reviewed full commit SHA. Publish through the existing trusted
   workflows, then check public package hashes and fresh consumers. Retain the
   release evidence before updating dependent bindings.

Do not claim full CSS inline parity or PDF standards conformance. The optional
dedicated PDF/VT validator remains a separate, unconfigured gate. Ordinary PDFs
using unembedded Standard 14 faces can also have host-dependent native previews;
the embedded-font fixtures avoid that dependency.
