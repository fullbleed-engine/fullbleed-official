# 2.6.0a5: component tables and inline spacing

Python prerelease: `2.6.0a5`, tag `v2.6.0a5`. Cargo source version: `2.6.0-alpha.5`.

This candidate merges the qualified stable 2.5.30 inline-spacing correction and
2.5.31 rich-cell tagging correction into the existing component branch. Preserve
the alpha's logical table-cell fragmentation, authored diagnostics, flex/grid
semantics, styles, named parts and static Bootstrap/HTML authoring surfaces.
This is a Python prerelease; publishing the Rust crate remains separate.

The published alpha 4 fails 135 of the 180 saved-PDF table-tagging controls; its
45 plain/CSS-bold/paragraph controls pass. Preserve those actual failed PDFs.
Its paired Northstar/Common Ground examples and accessible guide render in fresh
baseline captures, and all three isolated goldens match alpha 4 expectations.

The alpha has logical oversized-row splitting that is absent from stable 2.5.31.
The twelve-paragraph repeated-header input from stable issue #99 completes as two
pages on public alpha 4, with every text marker extracted once. This is a baseline
observation. Require candidate checks and visual/structural verification before
claiming the merged alpha preserves that behavior or handles other row layouts.

Required gates, in addition to the [initial alpha runbook](2.6.0a1-runbook.md):

1. Build and install the candidate wheel, generate agent artifacts from that
   runtime, rebuild and install the final wheel. Check synchronized metadata,
   installed-package behavior, generated contracts/stubs, licensing and Skill.
2. Retain the public alpha 4 negative table controls. Run all 180 native table
   cases on the candidate and compare text, paint, headers, alternatives and
   independent previews. Investigate every changed output; a stable-branch
   result does not establish component-alpha behavior.
3. Author rich DataTable and Bootstrap table cases with components, including
   paragraphs, emphasis, lists, figures, nested tables and an oversized rich
   row. Exercise direct/prepared PDFs and both HTML export modes. Inspect the
   saved PDFs for unique content ownership, preserved reading order, meaningful
   header relationships, text retention and repeated-render determinism.
4. Run external PDF/UA validation on retained saved outputs. Preserve failures
   and stderr, including known caption-containment rules from stable issue #98.
   Recheck the accessible guide's actual PDF and its negative control. A source
   accessibility report or passing profile boolean alone is insufficient.
5. Run focused and full Python/native suites and the component authoring,
   Bootstrap, typography, flex, SVG, inset-shadow, typing and editor gates.
   Verify standalone HTML in a browser. Static exports must remain static.
6. Compare every changed golden against fresh public alpha 4 output and the
   relevant retained stable/browser evidence. Review the Northstar invoice,
   Common Ground report and accessible guide at page level. Preserve parity
   between component and HTML/CSS authoring. Do not refresh references merely
   to pass a check; keep historical downloads and records immutable.
7. Qualify the final committed source through Windows/Linux CI and a fresh
   independent corpus run. Retain every pre-existing failure and disputed
   reference; review changed PDFs, rasters, scores and verdicts individually.
8. Require the exact-tag prerelease pipeline, all fifteen platform wheels and
   the source distribution. Download public artifacts, verify their hashes and
   run fresh public component consumers. Confirm normal pip resolution retains
   the stable channel and GitHub's latest stable release is not replaced.
9. Publish updated source kits and documentation only after registry/readback
   checks. Verify the downloadable projects, browser editing flow, authored
   exports and live assets. Preserve the alpha 4 guide and original downloads.

These are publication requirements, not a claim that the candidate is released.
Complete CSS/Bootstrap parity, external-PDF coverage, cross-language API parity,
general standards conformance and independent usability remain separate claims.
The dedicated PDF/VT validator is still unconfigured.

The component gate covers 208 saved PDFs (13 authored table families, four
profiles and four export/rendering routes). Public alpha 4 fails its 156 tagged
outputs; the candidate passes the content-ownership checks. All retained native
and component table previews match their alpha 4 pixels and preserve text,
header relationships and figure alternatives. These checks have a limited scope:
the oversized component fixture retains an orphaned caption page and existing
external table-column consistency failures on continuation rows. Do not present
that stress fixture as a fully conforming or polished document.

The only changed local golden is Acme's brand baseline at unit line height:
72.75pt becomes 72pt from the page top, matching the retained independent Chrome
measurement used for stable 2.5.30. The changed pixel rectangle is
(69, 82, 542, 148) on the 1224 by 1584 preview. The rest of that page and the other
two golden cases are unchanged. Retain the before/after measurements and images.
