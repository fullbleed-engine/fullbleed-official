# Fullbleed 2.5.4 release runbook

This patch fixes native preview text advances for unembedded Standard 14 fonts
whose PDF font dictionaries omit `/Widths`. Publish from a clean annotated
`v2.5.4` tag after all checks pass.

## Build and verify

Keep Python, Cargo, the CI smoke version, release defaults, and generated agent
artifacts synchronized at 2.5.4. The audit crate remains 0.1.3 and the optional MCP
adapter remains 0.1.1. Historical example pins retain their verified versions.

Run `python tools/generate_base14_metrics.py --check`. This checks the original
source hashes and exact generated tables. Keep the upstream AFMs, `MustRead.html`,
Adobe Glyph List files, license text, and source manifest together. Preserve their
original bytes and the derivative notices in `THIRD_PARTY_LICENSES.md`.

Build and install a wheel in an isolated environment. Generate agent artifacts
with `tools/generate_agent_contract.py --python PATH --json`, rebuild and reinstall
the final wheel, and run the generator with `--check`. Build the sdist from the
same final source; do not hand-edit the generated agent files.

- Run the `base14_preview` Rust regression tests and `tests/test_fullbleed_base14_preview.py`.
- Run `python -I tools/smoke_base14_preview.py --out target/base14-preview` against
  the installed wheel. Retain the 30 comparisons, source PDFs, previews, and
  incorrect-width/blank controls. Require the check to fail on the earlier runtime.
- Run the full Rust and Python suites, with `FULLBLEED_TEST_INSTALLED_NATIVE=1`
  for Python. Require Linux and Windows CI, including the retained preview gate.
- Render the documentation's actual quickstart PDFs using the public earlier
  runtime and the candidate. Inspect the affected native previews visually and
  compare the same PDF files with an independent renderer. Confirm the retained
  PDF bytes and embedded-font preview fixtures are unchanged.
- Run installed-package smoke, generated-contract checks, deterministic goldens,
  CSS status, license integrity, release metadata checks, and the bundled Skill
  validator documented in the contributor workflow.
- Require the complete release workflow's platform-wheel, installed-package,
  Rust, source-distribution, and existing print-profile checks.

The Rust regressions cover all 14 font names, encoding differences, Symbol and
ZapfDingbats mappings, character/word spacing, horizontal scaling, explicit widths,
embedded replacement programs, and separation of visible glyphs from ToUnicode
text. The installed-package gate compares implicit widths with independent
explicit-width fixtures in the same runtime. It is not an outline-parity test.
Those fixtures explicitly register bundled Noto faces under the PDF font names,
so missing system substitutes cannot make two blank images pass the comparison.

## Publish and verify

Publish through the configured PyPI trusted publisher and crates.io workflow.
Retain the exact source tag, successful CI evidence, registry metadata, and hashes.
Verify public distributions against release artifacts, install the public wheel
into a fresh environment, and rerun the preview smoke before claiming availability.

Native PNG hashes may change for affected unembedded fonts. Review the corrected
images before accepting a new baseline. Authoring measurements and emitted PDF
bytes are not intentionally changed; equality claims cover retained fixtures only.
The existing optional dedicated PDF/VT validator remains unconfigured. Its skipped
check does not establish independent conformance.
