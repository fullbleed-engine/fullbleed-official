# 2.5.25: Python component authoring

The Python UI surface gains named text/document elements, rich children,
`StyleSheet`, explicit layout props, and a direct document-to-PDF/PNG path.
Artifact rendering supplies small overridable layout defaults, so standalone
rows, stacks and grids do not depend on scaffold CSS.

Nested children and ordered generators are normalized at construction. Booleans
are conditional placeholders; HTML boolean attributes remain presence-based,
while ARIA/data values serialize as strings. Invalid names, cycles and children
on void elements fail explicitly. Style composition preserves quoted strings,
data URLs, comments and nested component blocks. Decorated function metadata is
preserved. No Rust rendering behavior or required dependency changes.

## Verification

- Build and install the final wheel, generate agent artifacts from it, rebuild,
  reinstall, and verify generated artifacts and release metadata.
- Run the focused UI tests and full Python suite with
  `FULLBLEED_TEST_INSTALLED_NATIVE=1` and the documented test-only PDF readers.
- Run `python -I tools/smoke_component_authoring.py`: five invoice data variants
  and standalone row/stack/grid layout through the installed package. Retain
  PDFs, PNGs and `verification.json`; inspect page layout before release.
- The CI wheel jobs run this smoke check on Windows and Linux and retain the
  `component-authoring-*` artifacts. The normal engine and release gates remain.
- Check the public wheel after publishing. Do not infer an accessible PDF
  conformance result from the component structural validator.

The Node component API is a local prototype, held while Python authoring is
refined. Rust/.NET ports are follow-through work, not part of this release.
