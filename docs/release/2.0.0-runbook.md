# Fullbleed 2.0.0 Release Runbook

Status: release candidate

This runbook validates and publishes the dependency-free `v2.0.0` release.
Release from the exact annotated tag; never publish from an uncommitted or
different checkout.

## Release Contract

- `Cargo.toml`, `Cargo.lock`, and `pyproject.toml` report `2.0.0`.
- `fullbleed_audit_contract` reports `0.1.2`, and the root dependency requires
  that version.
- The normal, all-feature, and build Cargo graphs contain only `fullbleed` and
  `fullbleed_audit_contract`.
- The audit-contract graph contains only itself.
- Python build requirements, runtime requirements, and the `api` compatibility
  extra contain no packages.
- Wheels remain tagged `cp310-abi3` and cover standard CPython 3.10 through
  3.14 on all 15 declared platforms.
- Both Rust crates and the Python distribution remain MIT licensed. Bundled
  third-party assets retain their recorded licenses.

## Clean-Checkout Validation

Run from the proposed release commit:

```powershell
python tools\check_release_metadata.py --expected-version 2.0.0 --json
python tools\check_license_integrity.py --json
cargo fmt --all --check
cargo test --locked
cargo test --locked --features python,svg_raster
cargo check --locked --all-targets --all-features
cargo tree -e normal --all-features
cargo tree -e build --all-features
python build_backend\fullbleed_build_backend.py wheel --out target\validate-wheel
python -m pip install --force-reinstall target\validate-wheel\*.whl
python -m pytest -q
python tools\generate_css_parity_status.py --check --json
python tools\check_release_worktree.py --json
```

The expected graph is:

```text
fullbleed 2.0.0
└── fullbleed_audit_contract 0.1.2
```

The Windows extension must depend on `python3.dll`, never a versioned
`python3XY.dll`. Linux and macOS extensions resolve CPython symbols from the
loading interpreter.

## Packaged Rust MSRV Gate

The audit contract must be packaged alongside the main crate so the prepublish
consumer can patch crates.io resolution to the exact local audit artifact:

```powershell
rustup toolchain install 1.85.0 --profile minimal
rustup run 1.85.0 python tools\smoke_crates_consumer.py --expected-version 2.0.0 --json
cargo publish --locked --dry-run --manifest-path crates\fullbleed_audit_contract\Cargo.toml
```

The consumer lockfile must contain exactly the consumer, `fullbleed`, and
`fullbleed_audit_contract`. A main-crate `cargo publish --dry-run` is performed
by automation after audit-contract 0.1.2 is published and visible in the
crates.io index.

## Python Distribution Gate

Build without build isolation dependencies:

```powershell
python build_backend\fullbleed_build_backend.py wheel --out dist
python build_backend\fullbleed_build_backend.py sdist --out dist
```

Verify that the wheel contains `fullbleed/_abi.py`, the native extension,
license files, runtime specifications, and the CycloneDX SBOM. The SBOM must
list only `fullbleed_audit_contract` beneath the root component. Build a second
wheel from the sdist and require byte-identical output for the same target and
source epoch.

The release workflow builds and installs:

- manylinux2014: x86-64, x86, ARM64, ARMv7, s390x, ppc64le;
- musllinux 1.2: x86-64, x86, ARM64, ARMv7;
- Windows: x86-64, x86, ARM64;
- macOS: Intel and Apple silicon.

The x86-64 manylinux wheel is additionally installed on Python 3.10, 3.11,
3.12, 3.13, and 3.14.

## Tag and Publish

1. Confirm all required gates pass on a clean worktree.
2. Create and push an annotated tag:

   ```powershell
   git tag -a v2.0.0 -m "Fullbleed 2.0.0"
   git push origin v2.0.0
   ```

3. Dispatch `Publish crates.io` with `release_tag=v2.0.0` and
   `publish=false`; review retained package evidence.
4. Dispatch the same workflow with `publish=true`. It publishes
   `fullbleed_audit_contract 0.1.2`, waits for propagation, performs the main
   dry run, then publishes `fullbleed 2.0.0`.
5. Let the tag-triggered release workflow build and smoke all wheel targets.
6. Review the aggregated 15 wheels plus sdist, then authorize PyPI publication.
7. Publish the same immutable artifacts on the GitHub `v2.0.0` release.

## Post-Publish Checks

```powershell
cargo info fullbleed_audit_contract@0.1.2
cargo info fullbleed@2.0.0
python -m pip install --no-cache-dir fullbleed==2.0.0
fullbleed capabilities --json
fullbleed doctor --strict --json
```

Confirm registry license metadata is MIT, packages are not yanked, PyPI exposes
all expected files, and a clean environment can render a PDF and PNG preview.
Published versions and files are immutable; corrections require a new version.
