# Fullbleed 2.5.2 release runbook

This patch ships the shared MCP input guidance and corrected side-effect hints
merged in PR #20. It preserves input/output validation constraints and rendering
behavior. Publish from a clean annotated `v2.5.2` tag after the required checks.

## Package preparation

Keep Cargo, Python, CI, release defaults, and generated core artifacts at 2.5.2.
The audit crate remains 0.1.3 and the optional MCP adapter remains 0.1.1; its
`fullbleed>=2.5.1,<3` requirement already permits this update. Existing examples
pinned to earlier verified engine releases can retain those pins.

Build and install a candidate wheel in an isolated environment. Run
`tools/generate_agent_contract.py --python PATH --json`, then rebuild and reinstall
the final wheel so its bundled contract matches the source. Run the generator
again with `--check`. Do not hand-edit generated agent artifacts.

## Required verification

- Check version synchronization, license integrity, generated MCP metadata, and
  the clean release worktree.
- Run the focused MCP and agent-contract tests, then the full Python suite using
  the installed native engine.
- Run `tools/smoke_installed_package.py --expected-version 2.5.2 --json`, the
  installed stdio smoke, and the locked official MCP client SDK smoke.
- Exercise all eleven tools, including asset locking, preview defaults, explicit
  verification checks, reusable compiled handles, and both binding modes. Compare
  the fixture PDFs and PNGs with the published 2.5.1 baseline and retain hashes.
- Check deterministic goldens, CSS status, and the bundled Skill validator.
- Require CI and the release matrix for the final source: fifteen ABI3 wheels,
  nineteen installed-wheel checks, the sdist, Rust MSRV checks, and the existing
  print-profile gate. Preserve raw reports and artifacts.

The internal print-profile checks and the separate-parser checks retain their
existing limits. Dedicated ISO PDF/VT conformance and directory quality scores
must not be inferred from this metadata update.

## Publication and public verification

Publish the validated distributions through the configured PyPI trusted publisher.
Publish the matching crate through the crates.io workflow. Retain registry
metadata, artifact checksums, and the GitHub release with the exact source tag.
Verify a fresh public installation, tool discovery, all-tool fixture execution,
and the official MCP SDK check before claiming the update is available.

After the public wheels exist, update the optional container's pinned requirements
from their Linux wheel hashes and run the container workflow. Refresh the Glama
entry only against that validated source; inspect its actual runtime tool schema
and retain the resulting build/introspection evidence. The MCP registry adapter
version remains 0.1.1 because its package and entrypoint have not changed.

Update the website's pinned Skill installation example only after `v2.5.2` is
public and a fresh GitHub CLI installation from that tag has been verified.
