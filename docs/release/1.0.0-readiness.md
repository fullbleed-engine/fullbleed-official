# Fullbleed 1.0.0 Release Readiness

Date: 2026-05-25

## Release Stance

Fullbleed 1.0.0 is scoped as deterministic infrastructure software for static
HTML/CSS/SVG/image-to-PDF generation. The launch claim is broad static-document
coverage with diagnostics, reproducibility, and standards-oriented profile
evidence. It is not browser-equivalent rendering.

## Artifact Policy

Release commits should contain:

- Source code, tests, fixtures, docs, and package manifests.
- Intentional fixture definitions such as the inline/SVG/image torture fixture.
- Generated status ledgers only when the file is already source controlled and
  the release checklist requires it to be refreshed.

Release commits should not contain:

- `output/` render artifacts.
- `_css_working/tmp/` outputs.
- Root `fullbleed_css_fixture_*.jsonl` traces and `fullbleed_preflight*` logs.
- Local ignored example corpora, generated example outputs, and vendored test
  assets.
- Local notes and scratch reports.
- `.pytest_cache`, local wheels, virtual environments, or installed extension
  binaries such as `*.pyd`.

## Remaining Final Handoff

1. Commit or otherwise preserve the intended release source/docs/tests.
2. Confirm `python tools/check_release_worktree.py --json` passes.
3. Rebuild final wheels from that clean commit with `python,svg_raster`.
4. Install each wheel and run installed-wheel smokes.
5. Publish only after the exact release commit has passed the runbook.
