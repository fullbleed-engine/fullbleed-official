# Stable v2.5.46: optional compiled batch reports

This additive API gives Rust and Python batch callers a PDF plus ordered record
diagnostics. Existing byte-only calls retain their signatures and output.

## Required evidence

1. Retain the public 2.5.45 negative control: fixed and reflow batches can emit
   missing characters without returning a batch report. Compare direct and
   compiled output with independent PDF readers. These are synthetic cases,
   not an independent adoption case study.
2. Retain the implementation qualification: 1,432 native tests, 11 Rust
   doctests, 856 Python tests, and 52 focused Python checks with each of one
   and four workers. The new report suite has 15 cases per worker. Compare
   saved PDFs, rendered images and JSON reports across worker counts.
3. Build/install a final-version wheel, generate agent artifacts from that
   runtime, and rebuild/install the final wheel and sdist. Check synchronized
   metadata, contracts, installed behavior, package descriptions, licenses and
   the bundled Skill. Rerun report, fallback, ABI and contract checks with one
   and four workers. Final-source Windows/Linux CI is required separately.
4. Retain the native/WASI probe's report, page-range, byte-identity,
   cancellation and recovery checks. The initial implementation qualification
   matches 25 files across native one/four workers and the single-thread WASI
   host with eight workers requested. Independent readers check six PDFs and
   16 pages; this is fixture-specific evidence, not broad renderer parity.
5. Compare all 1,662 unchanged corpus fixtures with stable 2.5.45 using the
   same references and thresholds. Investigate changed pixels, verdicts or
   PDF bytes and retain failures and disputed references.
6. Publish through existing workflows after source review and release gates.
   Verify public distribution hashes and fresh Python/Rust consumers before
   calling the release shipped. Attach source, baseline and reader evidence.

## Scope and limitations

Coverage concerns the registered font selected for each final text run. Fixed
bindings do not select a new fallback font. Reports include static text,
replacement text and drawn Forms, with ordered page offsets and counts for
variable-length records. They do not inspect Base-14 fonts or text already
converted to images and are not shaping, layout or conformance validation.

The stable 2.5.45 corpus baseline is 1,624 PASS, 20 FAIL and 18 disputed
references; its all-pass gate is not green. Development uses a different
baseline. Dedicated PDF/VT validation remains unavailable. These checks do not
establish general CSS parity, accessibility, conformance or throughput.

Node 0.8.7 does not expose this batch API. Component authoring remains alpha.
Independent adoption is unconfirmed. Local qualification is retained under
`target/growth/first-document-feedback-20261029/compiled-glyph-diagnostics-20261030/`,
with final stable package checks in `release-2546/`.
