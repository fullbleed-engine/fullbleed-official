# Stable 2.5.36: wrappable table minimums

The release tag is `v2.5.36`. This patch is based on stable 2.5.35 and leaves the
component alpha and its percentage-column allocator outside the stable release.

Keep receipts and exact rendered outputs under
`target/growth/entrypoints-and-cjk-20261026/`.

## Release gates

1. Retain the public 2.5.35 calibration: 27 saved-PDF cases, including plain,
   inline-element, and block-element cells, wrapping cases, and controls that
   deliberately preserve an unbreakable minimum. Keep the 14 observed failures.
   Also retain the two fixed-layout wrapped-span failures that isolate the
   existing first-line placement issue independently of column sizing.
   Check definite child widths, nested widths, minimum widths, border-box
   sizing, and a cyclic-percentage control before accepting rich-cell shrinking.
2. Compare synthetic Japanese fixtures with an independent browser print
   reference using the same explicit fonts and UTF-8 input. Include the
   intentional `keep-all` overflow control. A public integration's source
   informed this probe; it does not establish that its deployed output is broken.
3. Run focused and full Rust tests. Build and install a candidate wheel before
   generating the agent contract, then rebuild and install the final wheel.
4. Run the focused and full Python suites, installed-package and release-metadata
   checks, license checks, and the bundled Skill validator. Require saved-PDF
   text completeness, physical glyph bounds, and repeat-render determinism.
5. Inspect the realistic Japanese table and minimal regression PDF renders.
   Compare unchanged golden fixtures using isolated copies, preserving all
   user-owned output files. Review any changed results rather than updating
   expectations to suppress them.
6. Review exact-source Windows/Linux CI and the unchanged independent CSS corpus
   against 2.5.35, retaining failures, disputes, thresholds, and references.
7. Publish only after release gates pass. Verify fresh public Python and Rust
   consumers against registry checksums and the qualified source.

The checked-in CJK font is a 44 KB test-only OFL subset with recorded provenance;
it is not a new bundled runtime font. General CJK typography, arbitrary-document
accessibility, and complete CSS conformance remain outside these fixture results.
