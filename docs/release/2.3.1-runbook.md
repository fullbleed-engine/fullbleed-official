# Fullbleed 2.3.1 release runbook

Status: release

This patch release fixes generated synthetic-bold Type 3 previews and registered-font compiled fixed-layout bindings. Release only from the exact annotated `v2.3.1` tag; registry artifacts are immutable.

## Release contract

- `Cargo.toml`, `Cargo.lock`, `pyproject.toml`, CI, README installation examples, generated agent artifacts, and release documents report `2.3.1`.
- `fullbleed_audit_contract` remains `0.1.3`; the crates workflow reuses that published version and publishes only the missing main-crate version.
- `fullbleed-mcp` remains `0.1.0` with `fullbleed>=2.3.0,<3`; this patch does not change its protocol surface.
- Wheels retain the `cp310-abi3` tag for CPython 3.10 through 3.14 across all 15 platforms.
- Core installation remains self-contained and gains no third-party Python, browser, system-PDF, system-font, or AI-vendor dependency.
- `fullbleed-agent-contract.json`, `cli_schema.md`, and `llms.txt` must be generated from the final installed wheel, never edited by hand or generated from an editable checkout.

## Source and installed-wheel validation

Run from the proposed release commit in a clean worktree:

```powershell
python tools\check_release_metadata.py --expected-version 2.3.1 --json
python tools\check_license_integrity.py --json
cargo fmt --all --check
cargo test --locked
cargo test --locked --features python,svg_raster
cargo check --locked --all-targets --all-features

python build_backend\fullbleed_build_backend.py wheel --out target\release-2.3.1\dist
python build_backend\fullbleed_build_backend.py sdist --out target\release-2.3.1\dist
python -m pip install --force-reinstall target\release-2.3.1\dist\fullbleed-2.3.1-*.whl
python tools\smoke_installed_package.py --expected-version 2.3.1 --json
python tools\generate_agent_contract.py --python python --check --json
python tools\generate_mcp_server_json.py --check --json
$env:FULLBLEED_TEST_INSTALLED_NATIVE = "1"
python -m pytest -q
python goldens\run_golden_suite.py --python python verify
python tools\generate_css_parity_status.py --check --json
python tools\check_release_worktree.py --json
```

Run the bundled Skill validator and the retained synthetic-weight/custom-font VDP diagnostic. Confirm that all requested weights are readable in finalized previews, all bound values replace their markers, and no `{{slot}}` text remains.

## Packaged Rust and Python gates

```powershell
rustup run 1.85.0 python tools\smoke_crates_consumer.py --expected-version 2.3.1 --json
cargo publish --locked --dry-run
python -m twine check target\release-2.3.1\dist\*
```

Install and smoke the built wheel and sdist rather than an editable checkout. Verify MIT metadata, specifications, CycloneDX SBOM, Stable ABI tags, deterministic hashes, and the exact Cargo package file set.

## Publish order

1. Commit and push the clean release source.
2. Create and push annotated tag `v2.3.1`.
3. Let the tag-triggered `Release` workflow validate and build the complete 15-wheel plus sdist distribution set.
4. Dispatch `publish-crates.yml` for `v2.3.1` with `publish=true`.
5. Dispatch `release.yml` at `v2.3.1` with `publish_pypi=true` so trusted publishing uploads the exact validated distribution set.
6. Create the GitHub 2.3.1 release from `ReleaseNotes.MD` and attach the validated wheels, source distribution, and SHA-256 manifest.

Confirm PyPI exposes all 15 ABI3 wheels and the sdist, crates.io reports MIT and an unyanked `2.3.1`, and both registries resolve to the same annotated release source.
