# Stable 2.5.39: embedded font identity in native previews

Release tag: `v2.5.39`, following stable 2.5.38. Evidence is retained under the
main checkout's `target/growth/bindings-wrapping-20261026/template-overlay-guide-20261027/`.

## Required release evidence

1. Retain the public 2.5.38 wheel as the negative control, verify its registry
   checksum, and run the new composition and independently merged-page cases.
   Keep the original certificate PDF, incorrect native images, independent
   text/painting, and font-label counterfactual used to isolate the defect.
2. Build and install the candidate wheel, generate all agent artifacts from
   that installed runtime, then build and reinstall the final wheel and sdist.
   Keep Python, Cargo, generated contracts and CI versions synchronized.
3. Run focused preview/font tests and the full native and Python suites,
   installed-package smoke, contract checks, release metadata, package
   description, license integrity and the bundled Skill validator.
4. Check the saved PDFs with independent readers. Compare the candidate's
   previews with single-document controls and isolated-page controls, keep the
   regular/bold and reversed-subset cases, and visually review the original
   certificate. Check that this preview fix leaves the existing PDF bytes and
   unaffected preview controls unchanged.
5. Require exact-source Windows/Linux CI. Run the pinned full CSS corpus with
   unchanged inputs, references and thresholds and compare with the qualified
   stable predecessor. Preserve existing failed and disputed conclusions;
   an all-pass gate must not be reported as passing when failures remain.
6. Publish through the existing release workflows only after qualification.
   Check distribution descriptions, registry metadata/checksums and fresh
   public Python/Rust consumers. Carry the fix to the development branch too.

These gates establish the reported font-subset correction and bounded
regression results. They do not prove general raster parity, performance,
accessibility, or PDF standards conformance. The component API remains alpha.
