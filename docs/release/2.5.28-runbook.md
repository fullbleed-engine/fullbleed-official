# 2.5.28: signed inset shadows and clean unshadowed edges

Release tag: `v2.5.28`.

Inset shadows use the complement of a translated padding-box hole. Signed
spread and each corner radius are preserved; offsets are not capped at half
the box dimension. For a 120px-wide box, `inset 24px 0 0 -12px` paints a 12px
strip, and `inset 100px 0 0 0` reaches 100px. Table cells share the geometry.
Zero-blur shadows remain vector, and zero-area shadows paint nothing.

Rectangular holes use one fill of their exact intersected difference. Rounded
holes stay within their enclosing ring path. This avoids antialiased clipping
leaking paint onto unshadowed edges. Blurred shadows retain the kernel-support
margin, including contributing off-page pixels. Native previews apply the
destination clip after filtering; general foreground filters keep their behavior.

## Verification and publication

1. Build and install the versioned wheel. Generate `fullbleed-agent-contract.json`,
   `cli_schema.md` and `llms.txt` from that runtime. Rebuild and install the final
   wheel containing those artifacts; check release metadata and the bundled Skill.
2. Run the full Python suite and installed-package smoke checks. Run
   `tools/smoke_inset_shadows.py --pdfium --out target/inset-shadows` with the final
   installed wheel. Retain the 27 scenarios, direct and compiled PDFs, native and
   finalized previews, PDFium rasters and 16 clear-region checks at 300 DPI.
   Compare their output with the qualified feature build and inspect the images.
3. Use the clean GitHub checkout for the worktree gate and full release pipeline,
   including native tests, print-profile preflight, the 15-wheel matrix, sdist,
   platform smoke checks and the `release-inset-shadows` artifact. Complete the
   exact-tag crate workflow before claiming Rust registry availability.
4. Verify fresh public PyPI and crates.io consumers, installed versions, registry
   metadata and distribution hashes. Exercise signed spread, translated rounded
   holes and clear edges in the downloaded artifacts. Retain evidence beyond CI
   artifact expiration, then publish the GitHub release with its distributions,
   verification record and checksums.

The clean-checkout gate runs in CI; a local dirty-worktree result must not be
reported as a pass. A tag alone does not prove package publication or verification.
