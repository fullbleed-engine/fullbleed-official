# Fullbleed 2.5.9 release runbook

This patch fixes overlapping wrapped text after styled inline content and
preserves collapsed-space semantics through inline wrappers. Publish from a
clean annotated `v2.5.9` tag after these checks pass.

1. Synchronize Cargo, Python, CI, release defaults, and generated agent artifacts.
   Build and install a wheel; regenerate agent artifacts with
   `tools/generate_agent_contract.py --python PATH --json`. Rebuild and install
   the final wheel, then run the generator with `--check`.
2. Run the inline wrapping/spacing Rust regressions, the complete default and
   Python/SVG Rust suites, and the packaged-crate MSRV check. Run focused
   installed-native inline, text, and font Python tests, followed by the full
   suite with `FULLBLEED_TEST_INSTALLED_NATIVE=1`.
3. Install development-only `pypdf==6.19.0`, `pypdfium2==5.14.0`, and
   `pillow==12.3.0`. Run
   `python -I tools/smoke_inline_wrapping.py --out TARGET`. Require all 48 cases:
   plain and unstyled controls, code, color, background, padding, distinct fonts,
   combined decorations, long styled runs, adjacent DOM spaces, and proportional
   built-in fonts, across direct,
   fixed, reflow-throughput, and reflow-compact rendering. Check word positions,
   wrapping, single-copy content, and native/independent previews. Fixed output
   uses a variable slot wide enough for its replacement; its content-stream
   order is not claimed to be the visual order. Compare Helvetica and Times
   word origins against whole-string controls to detect excessive word spacing.
4. Retain the published 2.5.8 negative control. It must fail the styled wrapping
   checks while plain controls pass. Inspect representative native and PDFium
   previews and the actual Markdown starter PDF that exposed the bug.
5. Run existing font, styled-text, reproducibility, golden, and print-profile
   gates. Require Linux/Windows CI and retain its artifacts. Dedicated PDF/VT
   validation remains explicitly unverified without that optional validator.
6. Publish validated wheels/sdist and the crate through the trusted workflows.
   Verify public hashes and fresh installed consumers, then retain release
   assets and workflow results.

Review changed line breaks, pagination, and hashes instead of rewriting historic
release evidence. This is a focused LTR collapsed-whitespace correction, not a
claim of complete CSS inline layout conformance. Node/.NET bindings and browser
assets require separate rollout and verification.

word-fragment measurement moves it approximately 0.93 pt to the right. Extracted
text is identical. At 144 dpi, native and PDFium differences are confined to that
label; the rest of the invoice and the other golden cases remain unchanged.
Retain both PDFs, both native/independent previews, and the word-bound comparison
when refreshing this current test baseline. Historical example output stays at
its original version.

Helvetica `ALPHA` prefix advances 39.348 pt before layout snapping using the PDF
font metrics instead of the old 36 pt heuristic; the following fixed-size elements move accordingly.
Retain both PDFs, native/PDFium previews, and content streams when updating its
current position assertions and stability hash. Text, element sizes, and order
remain unchanged. The showcase text checks normalize extractor whitespace so
positioned word chunks still satisfy complete-phrase and record checks.

Execute the notebook and all three web-framework examples with the installed
wheel. Their complete-phrase checks also normalize extractor whitespace. Review
the current web example's saved preview against public 2.5.8 before refreshing
it; retain both versions and independent text/pixel comparisons. The reviewed
invoice remains one page with identical independently extracted text.
