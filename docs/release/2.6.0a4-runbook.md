# 2.6.0a4: static components and saved-PDF group opacity

Release tag: `v2.6.0a4`. Python version: `2.6.0a4`.
Cargo source version: `2.6.0-alpha.4`.

This candidate ports the qualified stable 2.5.29 isolated-transparency-group
reader correction into the Python component alpha. The PDF writer, component
API, owned styles, named parts and Bootstrap 5.0.0 kit retain their existing
behavior. PDF and HTML exports remain static. Previously published alpha and
preview artifacts keep their original bytes.

Follow the package, authoring, typing, editor, clean-release and public-registry
gates in the [initial alpha runbook](2.6.0a1-runbook.md), using these versions.
Generate agent artifacts from the built and installed candidate, rebuild and
install the final wheel, then check those artifacts against that runtime. This
is a Python prerelease; Rust registry and other binding releases are separate.

Additional qualification for this update:

1. Run the expanded SVG gate against the published 2.6.0a3 wheel before the fix.
   Retain its failures, PDFs, layout previews, saved-PDF previews and independent
   PDFium images. Keep every expected color and tolerance unchanged.
2. Run the six native isolated-group tests, the focused Python component tests,
   the complete Python suite and complete native suite against the final source.
   Preserve the earlier font cascade, semantic flex/grid and inset-shadow fixes.
3. Run `tools/smoke_svg_styles.py` for all 54 inputs and 810 checks, including
   direct, compiled, fixed and reflow PDFs. Compare the candidate with the
   published alpha 3: investigate every changed PDF byte or layout/independent
   raster and review the corrected saved-PDF previews.
4. Run `tools/smoke_component_svg.py` for reusable defaults, class inheritance,
   named-part group opacity and both HTML export modes. All twelve records must
   check repeated saved-PDF previews as well as independent PDF paint. Retain
   the published alpha 3 as a failing control for the same component inputs.
5. Re-run the existing component examples, Bootstrap catalog, golden suite,
   typography, flex, inset-shadow, typing and standalone HTML checks. Compare
   their existing PDF, preview and HTML artifacts with the published alpha 3.
   Do not refresh expected output merely to make a check pass.
6. Run the independent CSS corpus for the final alpha source. Compare its
   results and output with alpha 3; retain failures and disputed references.
   Historical stable and alpha results remain historical evidence, not a claim
   that this reader correction establishes complete CSS or browser parity.
7. Qualify the exact committed source through CI and the release pipeline for
   all fifteen Python wheels and the sdist. Check Windows and Linux SVG and
   component artifacts. Record independent-reader font rasterization differences
   separately from Fullbleed output and authored SVG paint expectations.
8. Download the public distributions and install the final alpha in a fresh
   environment. Re-run component exports and saved-PDF checks. Confirm ordinary
   pip resolution still chooses the stable channel, and publish the GitHub
   release as a prerelease without replacing the latest stable release.
9. Update the public alpha guide and download only after registry and release
   readback. Preserve the earlier alpha downloads and verification records.

These are required release gates, not claims that the candidate is published.
The dedicated PDF/VT validator remains unconfigured. General external-PDF,
accessibility and complete Bootstrap/CSS parity, stable API promotion and
independent author feedback remain separate work.
