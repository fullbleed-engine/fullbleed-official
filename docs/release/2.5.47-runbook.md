# Stable v2.5.47: bundled asset CLI workflow

## Scope

Use `python -m fullbleed render --html invoice.html --css invoice.css --asset "@inter" --out invoice.pdf`
with `font-family: Inter` in the CSS. This registers the package's existing Inter
font without a separate install. Inter is also discoverable through
`assets list` and usable through `info`, `install`, `verify` and `lock`.
Rendering, vendoring and lock entries resolve the same bytes from one catalog.

Supported legacy Bootstrap, Bootstrap Icons and Noto Sans references remain
valid. Explicit built-in versions must be included in the package; a different
version cannot relabel those bytes. Existing destination files with different
contents are preserved and reported as conflicts. Matching files can be
installed again. Inter vendoring copies the complete bundled OFL notice.

This release changes Python CLI/package assets and documentation. It does not
change the Rust rendering implementation or promote the component alpha.

- Run the bundled-asset tests against an installed wheel with source conftest
  disabled. Network entry points must fail if called. Check real PDFs, embedded
  fonts, glyph diagnostics, legacy aliases, license bytes, lock integrity,
  idempotent installs and preservation of different existing files.
- Retain Windows/Linux source-CI outputs from those same tests.
- Run focused CLI checks and the full Python suite; retain any skips accurately.
- Build and install the final versioned wheel, regenerate agent artifacts from
  that installed runtime, then build and install the final distributions.
- Check generated contracts, release metadata, installed-package behavior,
  package descriptions, license integrity and the bundled Skill.
- Publish only the qualified source through the existing trusted release
  workflow. Verify the public wheel and rerun the installed bundled-asset tests
  against a fresh registry installation before claiming public delivery.
