# 2.5.17 Rust API onboarding release

Target release tag: `v2.5.17`.

1. Confirm that Rust source changes contain documentation only. Run Rustdoc
   examples and build the reference with broken internal links treated as errors.
   Run the three file-writing examples from the documentation verbatim as
   standalone programs, including missing/invalid font checks. Retain PDFs,
   previews and independent-reader inspection.
2. Build and install the final-version wheel, regenerate agent artifacts from
   that installed runtime, then rebuild and check the final installation. Run
   focused contract/metadata tests, the full Python suite, installed-package
   checks, license checks and bundled Skill validation.
3. Require normal Windows/Linux CI on the exact release-preparation commit,
   including Rust tests, documentation builds, packaged consumers at the declared
   MSRV and the existing print-profile preflight. Review the generated API pages
   on desktop and mobile.
4. Tag the validated merge and publish through the existing trusted PyPI and
   crates.io workflows. Verify public registry versions/checksums and fresh
   Python/Rust consumers. Check the new version on docs.rs before reporting the
   hosted onboarding guide as available.

Rendering algorithms and dependencies are unchanged. The documentation examples
are evidence for those workflows, not a new CSS, PDF standards, performance or
cross-renderer parity result. The existing renderer limitations and the optional,
unconfigured dedicated PDF/VT validator are unchanged. Node and .NET package
versions are not advanced by this release.
