# Fullbleed agent acceptance suite

This suite tests whether an unfamiliar agent can use Fullbleed without hand-written product guidance. Each run starts in a blank directory. The agent receives only:

- the canonical `fullbleed.agent_contract.v1` artifact generated by the installed wheel;
- one machine-readable `TASK.json`;
- the PDF template fixture only for the template-overlay scenario.

The five first-party scenarios are an invoice, a naturally paginated report, an accessible PDF/UA document, a PDF-template overlay, and a 25-record compiled VDP job. The judge inspects every PDF, extracts required text, validates page counts and ordering, checks PDF/UA structure/profile signals, checks composition compatibility, and requires compiled-API evidence for VDP.

## Prepare a run

The target must be absent or empty. The command refuses to overwrite a non-empty directory.

```text
fullbleed agent-acceptance prepare --workspace agent-run --json
```

To prepare one scenario:

```text
fullbleed agent-acceptance prepare --workspace agent-run --scenario invoice --json
```

Point an external agent at each scenario's `TASK.json`. Do not give it the README, source tree, examples, or other Fullbleed documentation.

## Judge existing outputs

```text
fullbleed agent-acceptance verify --workspace agent-run --json
```

The process exits nonzero if any scenario fails. The JSON result uses `fullbleed.agent_acceptance_result.v1` and includes per-scenario failure codes.

## Run an external agent adapter

The harness can prepare, invoke, and judge any command-line agent. Arguments after `--agent-command` are passed without a shell. These placeholders are substituted independently in each argument: `{workspace}`, `{task}`, `{contract}`, and `{scenario}`.

```text
fullbleed agent-acceptance run --workspace agent-run --json --agent-command my-agent --task-file {task} --workspace {workspace}
```

The same paths are supplied as `FULLBLEED_ACCEPTANCE_WORKSPACE`, `FULLBLEED_ACCEPTANCE_TASK`, `FULLBLEED_AGENT_CONTRACT`, and `FULLBLEED_ACCEPTANCE_SCENARIO`. Stdout and stderr are retained in each scenario directory for auditability.

This harness deliberately does not bundle a model vendor or prompt framework. Its job is isolation and objective judging, so the same contract can be evaluated across unfamiliar models and agent runtimes.
